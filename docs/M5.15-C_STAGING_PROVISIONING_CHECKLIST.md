## 1. PostgreSQL 创建

- [ ] 在云厂商（或自托管）创建 Staging PostgreSQL 16
- [ ] 创建最小权限应用账号（仅业务库 DML，禁止 DDL 日常使用）
- [ ] 配置 `DATABASE_URL`（`postgresql+asyncpg://...`）到 `backend/.env`
- [ ] 执行 `alembic upgrade head`，确认 `current = 0023`
- [ ] 验证：`SELECT version();`、workspace 隔离、event_log、agent/product/approval/experiment 表
- [ ] 不要用 localhost 临时 pgserver 冒充 staging

## 2. Redis 创建

- [ ] 创建 Staging Redis（6.2+，启用持久化策略）
- [ ] 配置 `REDIS_URL` 到 `backend/.env`
- [ ] 验证：`PING`、Stream、consumer group、`XREADGROUP`、`XACK`、`XPENDING`
- [ ] 不要用本地临时 Redis 冒充 staging

## 3. Clerk Test Instance

- [ ] 在 Clerk Dashboard 创建 Test Instance（非 production）
- [ ] 获取并配置（仅 `.env` / secret store）：
  - `CLERK_JWKS_URL`
  - `CLERK_ISSUER`
  - `CLERK_AUDIENCE`
- [ ] 不需要则不引入 `CLERK_SECRET_KEY`；严禁写入 git / 文档 / 日志 / DB / trace

## 4. Test User A / B

- [ ] 创建 User A（加入 Organization A）
- [ ] 创建 User B（加入 Organization B）
- [ ] A 不得加入 B，B 不得加入 A
- [ ] actor_id 由 JWT `sub` 确定；邮箱仅作 display metadata，不作为主键
- [ ] 禁止使用 `agent` / `system` 作为 `sub`

## 5. Organization A / B

- [ ] 创建 Organization A 与 Organization B
- [ ] 记录 `org id`（仅 identity metadata，只存必要字段）

## 6. Org → Workspace Mapping

- [ ] 通过正式 API / migration / admin 机制写入 `workspace_identity_links`：
  - Org A → Workspace A（`enabled=true`）
  - Org B → Workspace B（`enabled=true`）
- [ ] 确认 `workspace_id + organization_id` 唯一约束生效
- [ ] 禁止用 `X-Workspace-Id` 强行切换 workspace（仅作路由提示，最终 workspace 由身份映射决定）

## 7. RBAC Seed

- [ ] 为 Workspace A 的 operator 配置：
  - `product.decision.approve`
  - `product.decision.reject`
  - `product.candidate.promote`
  - `product.experiment.start`
  - `calibration.approve`
  - `calibration.reject`
- [ ] 为 Workspace B 配置不同权限组合（用于隔离测试）
- [ ] Agent 不得获得 human permissions

## 8. Cloudflare Access Staging

- [ ] 创建 Staging Application（只保护 Nuotao Staging API / Console，不保护 production）
- [ ] 身份源选择 Clerk Test Instance（或等价 OIDC/SAML）
- [ ] 确认鉴权后向 Origin 注入 `CF-Access-Jwt-Assertion`
- [ ] 配置 `ACTOR_HEADER_NAME=CF-Access-Jwt-Assertion`
- [ ] 严禁信任 `X-Actor` / `body.actor`

## 9. ACTOR_PROVIDER=header

- [ ] `ACTOR_PROVIDER=header`
- [ ] `ACTOR_HEADER_NAME=CF-Access-Jwt-Assertion`
- [ ] 验证 curl/browser 无 header → `401`；invalid / expired / wrong iss / wrong aud → `401`；valid → PASS
- [ ] body.actor / X-Actor 必须被忽略或拒绝

## 10. Identity /me 验证

- [ ] User A 登录后 `GET /api/v1/identity/me` 返回：
  - `actor_id` / `organization_id` / `workspace_id` / `authentication_method` / roles/permissions
- [ ] 不得返回：JWT、raw token、secret、完整 email、credentials
- [ ] User B 再执行一次，必须得到不同的 actor / organization / workspace

## 11. Cross-workspace 验证

- [ ] User A：可访问 Workspace A；访问 B、approve B、promote B、start B experiment → `403/404`
- [ ] User B 反向验证
- [ ] `User A + X-Workspace-Id=B` → `403/404`
- [ ] Agent actor / body.actor / X-Actor 均不可绕过认证

- [ ] 目标：postgres / redis / llm / woocommerce / real_products / operator / rbac / sla / budget / retry / audit 全部 PASS
