## 三、P0：修订 SKU / Variation 身份模型

- 修订历史 NULL 回退设计。必须明确**三种身份状态：PRODUCT / VARIATION / UNKNOWN_LEGACY**。
- **历史数据不能因为 wc_variation_id 为空就自动认定为商品级记录。**
- 补充设计：
  1. 商品级和变体级唯一性约束。
  2. PostgreSQL 部分唯一索引及对应迁移 DDL。
  3. Product、ProductMapping、OrderItem、InventorySnapshot、成本快照之间的身份关系。
  4. 新订单如何记录 wc_product_id、wc_variation_id 和 variation_sku。
  5. 历史订单无法确定变体时如何保留 UNKNOWN_LEGACY。
  6. 71 行历史快照与 70 个有效变体的逐行核对结果。
  7. source_offer_id 与 WooCommerce 变体之间的映射关系，支持多供应商报价。
  8. 历史回填的可逆方案、冲突处理和数据校验。
- SKU 只能作为辅助识别字段，**不得重新作为唯一身份主键**。
- 本任务只交付设计、测试和迁移方案，**不执行任何生产数据库迁移**。

## 四、P1：加强 1688 库存同步测试

完善测试矩阵，至少明确覆盖：

- 库存为 0。
- 库存为 null。
- 库存字段缺失。
- 库存为负值或非法类型。
- 库存快照过期。
- 时间戳异常。
- 同一变体重复同步。
- 并发同步。
- 网络中断及重试。
- 映射缺失或多个映射冲突。
- 供应商库存与网站可售库存不一致。

继续保持：

- supplier_available_quantity 与 woocommerce_sellable_quantity 完全分离。
- 任何未知、缺失、异常、过期数据均不得直接覆盖 WooCommerce 可售库存。
- 补充测试报告、映射覆盖率、库存异常处理日志及幂等证明。
- **仅限测试环境。**
