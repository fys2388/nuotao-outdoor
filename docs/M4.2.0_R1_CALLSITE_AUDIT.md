# M4.2.0-R1 采购单状态变更路径全仓库审计

> 目的：穷尽列出所有能改变 `purchase_orders` 状态（尤其到达 `approved`）的代码路径，证明 R1 收口后无未授权绕过面。
> 方法：全仓库 grep `PurchaseOrder(` 构造、`update_purchase_order_status`、`.status = "approved"`、`UPDATE purchase_orders`，逐条甄别实体归属与调用链。
> 日期：2026-11-21

## 1. 审计结论（一句话）

**数据库 `purchase_orders` 表到达 `approved` 的路径，收口后仅剩一条**：`supply_chain.approve_purchase_order`（受 RBAC + 角色 + 身份三重校验）。其余构造点均产出 `draft` 或非审批态，旧 Fulfillment 旁路已封堵。

## 2. purchase_orders 表的全部状态写入点

| # | 文件 | 入口 | 产出状态 | 是否可到 approved | 收口状态 |
|---|---|---|---|---|---|
| 1 | `services/procurement_service.py:272` | Agent `create_purchase_order` | `draft` | ❌ | ✅ R0 已改（原硬编码 approved） |

| 5 | `api/v1/endpoints/supply_chain.py::update_purchase_order_status`（PATCH） | 状态端点 | 经 `PO_TRANSITIONS` | ❌（拒绝 approved） | ✅ R0 重写 |

## 3. 排除项：非 purchase_orders 实体

全仓库 grep 命中的大量 `.status = "approved"` / `new_status="approved"` 属**其他实体**，不在采购治理范围，列出以证清白：

- `activity_planner_service.py:451`（activity plan）
- `b2b_credit_service.py:1260` / `b2b_agreement_service.py:1163` / `b2b_credit.py:704`（B2B claim/accrual）
- `agent_suggestion_service.py:308,363` / `agent_approval_service.py:315`（Agent 建议审批队列，独立审批体系）
- `calibration.py:417`、`calibration run`
- `content_marketing_service.py:258`、`creative_service.py:2809,3501`、`marketing_learning.py:648`、`image_generation_service.py:321`（营销/创意/生图任务）
- `customer_privacy_service.py:338` / `customer_data.py:439`（数据主体请求）
- `listing_jobs.py:197,284`（listing 任务）
- `refund_service.py:301`（退款审批）

这些各有独立的审批/状态机，与 `purchase_orders.approved` 无关。

## 4. 第四套状态机（文件存储，非 DB 表）

`services/purchase_order_service.py`（经 `api/v1/endpoints/procurement_workbench.py` 暴露）：

- 存储：JSON 文件（`load_purchase_orders` / `save_purchase_orders`），**与 DB `purchase_orders` 表是两份数据**。
- 状态集：`pending / confirmed / ordered / shipped / international_shipped / completed / cancelled`。
- **不含 `approved`**，最高到 `confirmed`（人工确认后可去 1688 下单）。
- 结论：**无绕过审批面**（它根本没有 approved 概念）。属既知多状态机技术债 D-2，建议长期归一到 `PO_TRANSITIONS`。

## 5. 越界状态提示

`purchase_automation_service` 历史上产出过 `po_status="pending_approval"`（既非 `PO_TRANSITIONS` 也非 `PO_STATUS_FLOW` 合法态），由 `scripts/po_dedup_audit.py` 标记为未结。R0 已改为 `draft` 规避；彻底统一待 T0.5 数据模型迁移。
