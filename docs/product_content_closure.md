# 商品内容与媒体闭环

## 目标

确保从 1688 导入的产品在进入候选池、生成上架草稿和推送 WooCommerce 前，
同时具备可追溯的原始数据、结构化参数、媒体素材和目标市场文案。任何缺失的
关键内容都必须在进入下一个人工节点前暴露，禁止用中文标题或空图片静默上架。

## 主数据约定

商品主记录继续作为 B2C/B2B 共享商品中心，扩展数据使用 `attributes` 和
`meta`，避免在流程尚未稳定时频繁增加表字段。

- `description`：可读的原始商品描述，便于人工核查。
- `attributes`：结构化规格对象，例如材质、容量、防水等级。
- `meta.media.images`：1688 原图或已审核媒体 URL。
- `meta.supplier`：供应商快照。
- `meta.analysis.ai_recognition`：AI 产品识别结果。
- `meta.analysis.product_report`：17 字段产品报告。
- `meta.localizations.<language>`：目标市场文案版本。

本地化版本初始状态为 `generated`，必须人工确认后变为 `approved`。上架草稿和
WooCommerce 推送只允许使用目标市场语言已审核版本。

## 上架门禁

1. 商品名称或描述包含中文等非目标市场文字时，必须有已审核英文版本。
2. 上架草稿从已审核本地化版本读取标题、长描述、短描述和卖点。
3. 图片只从商品媒体记录读取；没有图片时可以保存草稿，但不得静默发布。
4. WooCommerce 回同步必须保留图片、属性和本地化引用，避免再次丢失。

## 当前流程

`1688 导入 -> AI 分析 -> 加入候选池 -> 保存原始内容/媒体 -> 生成目标语言文案
-> 人工确认 -> 商品上架审批 -> WooCommerce 草稿 -> 发布`

AI 只负责生成建议内容；上架状态和发布动作继续由人工审批控制。
