## 步骤 ① 选品入库

**目标**：贴一个 1688 链接，走 `/product-pipeline/import-from-1688` 一键导入

### 操作记录

1. 进入"商品与 AI 选品 → 商品工作台"（ProductPipeline 页面）
2. 在"1688一键导入"输入框填入 `https://detail.1688.com/offer/738470881485.html`
3. 点击"导入"按钮

### 发现的问题

**🐛 Bug #1（P0）**：前端 1688 一键导入字段名不匹配后端
- **现象**：点击"导入"按钮后无任何反馈，表单仍然空白，无错误提示
- **根因**：前端发送字段名 `url`，后端 Pydantic schema 期望 `url_or_id`
- **验证**：直接 curl `POST /api/v1/product-pipeline/import-from-1688` 传 `{"url":"..."}` 返回 422 `Field required: url_or_id`
- **修复方案**：前端 `frontend/src/pages/ProductPipeline.tsx` 中导入请求的 body 把 `url` 改为 `url_or_id`；或后端兼容两种字段名
- **严重程度**：P0 —— 用户以为导入成功，实际完全没生效，会误导运营

**🐛 Bug #2（P1）**：1688 Open API 调用返回 400 Bad Request
- **现象**：用正确字段名 `url_or_id` 重发请求，后端返回 `{"success":false,"error":"400 Client Error: Bad Request for url: https://gw.open.1688.com/openapi/param2/1/alibaba.product.get/2819733"}`
- **根因**：可能是 1688 API 凭证过期、被限流，或该商品 ID 已下架
- **修复方案**：检查 1688 API appKey/secret 是否有效；配置 1688 API 错误分类（凭证错误/限流/商品下架应给不同错误码）
- **严重程度**：P1 —— 不影响主流程（可手动录入），但一键导入功能不可用

### 绕过方案（继续测试）

### 发现的问题（步骤 ① 补充）

**🐛 Bug #3（P0）**：AI 产品分析失败 —— `unsupported provider 'sensenova'`
- **现象**：AI产品分析步骤显示 failed，错误信息：`Analysis failed: AI产品分析失败: unsupported provider 'sensenova'`
- **根因**：后端 AI provider 配置中未注册 `sensenova` 提供商
- **影响**：10字段识别 + 17字段产品报告完全无法生成，阻断后续分析复核
- **修复方案**：检查 `backend/app/core/settings.py` 或 `litellm` 配置，添加 `sensenova` provider 映射
- **严重程度**：P0 —— 核心 AI 功能完全不可用

**🐛 Bug #4（P1）**：SKU 生成格式不规范
- **现象**：生成的 SKU 为 `NT-便携不锈钢保温杯-5-09251534`，包含中文字符和日期时间戳
- **问题**：SKU 应仅含英文/数字/连字符，避免中文；日期戳格式不标准
- **影响**：同步到 WooCommerce 时可能出现编码问题
- **修复方案**：SKU 生成逻辑改为英文 slug（如 `NT-BOTTLE-500ML-20260925`），避免中文
- **严重程度**：P1 —— 可能导致同步失败或数据不一致

**🐛 Bug #5（P1）**：定价计算错误
- **现象**：1688 采购价 ¥25.00，系统生成售价 $50.00
- **问题**：按 `docs/product_selection_logic_v2.0.md` 的定价策略（采购价 5-8 倍），应该是 $125-$180；实际只涨了约 2 倍（¥25 → $50 ≈ ¥360 → $50）
- **根因**：定价算法可能没有按 V2.0 文档的倍数计算，或汇率/成本模型配置错误
- **修复方案**：检查定价算法，确保按采购价 × 倍数计算，且考虑汇率
- **严重程度**：P1 —— 定价错误会直接导致亏损

**🐛 Bug #6（P2）**：工作流耗时显示 0 秒
- **现象**：工作流实际执行了几秒，但页面显示"0 s"
- **问题**：耗时计算可能有 bug（时间戳未正确更新或时区问题）
- **严重程度**：P2 —— 不影响功能，但影响用户体验

**🐛 Bug #7（P2）**：上架数据不完整
- **现象**：完整描述为空，标签为空
- **问题**：工作流说明说"自动生成名称、描述、价格、SKU、分类、标签"，但实际只生成了名称、价格、SKU、分类，标签和完整描述缺失
- **修复方案**：检查上架数据生成逻辑，确保完整描述从商品描述生成，标签从核心卖点提取
- **严重程度**：P2 —— 影响上架质量

**🐛 Bug #8（P1）**：商品类目未选但分类 ID 为 15
- **现象**：未选择商品类目，但上架数据中分类为 "15"
- **问题**：分类 ID 15 是什么？应该是默认值还是随机分配？
- **严重程度**：P1 —— 分类错误会导致商品出现在错误的 WooCommerce 分类中
