# Nuotao AI OS 系统操作说明书：选品到采购

> 文档版本：v1.0  
> 更新日期：2026-09-13  
> 适用系统：`https://admin.nuotaooutdoor.com/`  
> 演示范围：1688 商品导入 → AI 产品分析 → 候选产品池 → 人工选品状态 → 供应商准备 → 采购订单创建 → 审批 → 下单 → 收货

## 1. 演示目标和硬性边界

本说明书用于让豆包在 Google Chrome 中按真实页面完成“选品到采购”浏览器演示。

必须遵守以下边界：

1. 只根据页面实际显示的内容操作，不得猜测按钮、字段、页面跳转或成功状态。
2. 页面与说明书不一致时立即停止，并截图说明差异，不得自行绕过。
3. 登录密码不写入演示截图、提示词或分享链接，由项目负责人在登录阶段现场输入。
4. AI 只提供分析和建议；候选通过、测试、胜出、上架审批、采购审批、下单和收货都必须人工确认。
5. “提交上架审批”只提交审批，不会直接发布 WooCommerce 商品。
6. “已确认收货”只更新采购订单状态；库存是否可用必须在 WMS 库存仓储模块另行核对。
7. 采购状态演示必须在 staging 环境或经负责人批准的演示采购单上进行，不得用真实供应商订单做状态实验。

| 截图节点 | 登录成功、分析完成、加入候选池、候选状态、采购草稿、审批、下单、收货 |

演示前先确认以下菜单和页面可打开：

| 页面 | 地址 |

## 4. 标准演示路径

### 4.1 登录经营控制台

1. 在 Chrome 打开 `https://admin.nuotaooutdoor.com/`。
2. 如果进入登录页，填写用户名 `admin`。
3. 由项目负责人输入登录密码。
4. 点击“进入控制台”。
5. 预期结果：进入经营总览，左侧出现“商品与 AI 选品”“B2C 零售”“B2B 批发”“供应链共享底座”等菜单。

异常处理：

| 页面现象 | 操作 |
|---|---|
| 用户名或密码错误 | 停止，由负责人确认账号 |
| 登录后仍返回登录页 | 刷新页面后重试一次；仍失败则停止 |
| 出现验证码 | 由项目负责人人工完成，不绕过 |

### 4.2 从 1688 导入并完成 AI 产品分析

1. 在左侧菜单点击“商品与 AI 选品”。
2. 点击“AI 产品分析”。
3. 确认页面标题为“1688 商品导入与 AI 产品分析”。
4. 在左侧“导入 1688 商品”输入框中粘贴一个或多个 1688 商品链接或商品 ID，每行一个。
5. 确认页面显示“已识别 N 条，单次最多 10 条”。
6. 点击“导入并分析”或“导入并分析 N 个商品”。
7. 等待进度完成，不得在分析中重复点击。
8. 预期结果：左侧“导入结果”显示成功记录，右侧出现“AI 识别结果（10 字段）”。
9. 点击成功记录，切换到“AI 识别结果”。
10. 点击“生成产品信息报告”。
11. 切换到“产品信息报告”，确认页面显示“产品信息报告（17 字段）”。

如果单个 1688 链接失效：

1. 在“导入结果”中确认失败原因。
2. 点击“重试”一次。
3. 仍失败时改用另一个有效链接，或使用左侧“手工录入（备用）”继续演示。
4. 不得把失败记录描述为分析成功。

### 4.3 加入候选产品池

1. 在“产品信息报告”页面确认已出现商品名称、类目、成本或价格等真实数据。
2. 点击“加入候选池”。
3. 预期结果：页面提示“已加入候选池并完成首轮评分，正在打开候选产品页”。
4. 系统会自动打开“候选产品与选品”页面。
5. 使用搜索框按商品名称、SKU 或来源链接找到刚加入的商品。
6. 确认列表显示“来源”“AI 评分”“落地成本”“状态”和“目标市场”。

如果缺少商品名称，系统会提示“缺少商品名称，无法加入候选池”。此时停止，补齐真实商品数据后再继续。

### 4.4 查看评分、成本和证据

1. 在候选商品行点击“查看”。
2. 在右侧详情抽屉确认以下内容：
   - 六维评分：利润、物流、需求、竞争、差异化、合规。
   - 评分证据：评分、来源、置信度和证据内容。
   - 最新成本：采购成本、总落地成本、成本版本和生效时间。
3. 如果评分缺失，点击“立即评分”或“重新评分”。
4. 预期结果：页面提示评分已重新计算并写入审计记录。

只允许展示系统实际返回的评分和证据，不得用口头估计替代页面数据。

### 4.5 人工推进选品状态

候选状态必须按以下顺序推进：

```text
待评估 candidate
  → 已通过 approved
  → 测试中 testing
  → 已胜出 winner
```

操作步骤：

1. 在详情抽屉点击“通过选品”。
2. 在弹出的确认框点击“确认”。
3. 预期结果：候选状态变为“已通过”。
4. 点击“进入测试”，确认后状态变为“测试中”。
5. 点击“标记胜出”，确认后状态变为“已胜出”。
6. 点击“提交上架审批”。
7. 在确认框点击“提交审批”。
8. 预期结果：页面提示“上架审批已提交，请到审批中心处理”。

说明：

- 该动作只提交审批，不直接发布商品。
- 不应通过多次点击跳过状态机。
- 如果“通过选品”“进入测试”“标记胜出”任一按钮不可见，说明当前状态不支持该动作，停止并核对状态。

## 5. 从选品转入采购

候选商品胜出不会自动生成采购订单。采购需要先确认供应商，再由人工创建采购单。

### 5.1 准备供应商

1. 在左侧“供应链共享底座”点击“采购与供应商”。
2. 如果已有用于本次演示的供应商，记录其“供应商编号”和“供应商名称”。
3. 如果没有，点击“新增供应商”。
4. 填写以下字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| 供应商编号 | `SUP-DEMO-001` | 必须唯一 |
| 供应商名称 | 真实供应商名称 | 不得使用虚构公司名 |
| 平台 | `1688` | 默认值 |
| 评级 | `A/B/C/D` | 按真实评估填写 |
| 店铺链接 | 1688 店铺地址 | 可选 |
5. 点击“创建”。
6. 预期结果：页面提示“供应商已创建”，供应商列表出现新记录。

### 5.2 创建采购订单草稿

1. 在左侧“供应链共享底座”点击“采购订单”。
2. 点击右上角“新建采购单”。
3. 在弹窗中确认标题为“新建采购单”。
4. 填写表头：

| 字段 | 演示填写建议 |
|---|---|
| 采购单号 | 默认自动生成，例如 `PO-20260913-153000`，也可按公司规则修改 |
| 供应商 | 选择 5.1 已确认的供应商 |
| 币种 | 中国采购默认 `CNY` |
| 运费 | 按真实报价填写，没有则填 `0` |
| 采购备注 | 可填写包装、标签、交期等真实要求 |

5. 在“采购商品”的“商品 1”中填写：

| 字段 | 示例 |
|---|---|
| SKU | 与候选商品或商品主数据一致的 SKU |
| 商品名称 | 与候选商品一致的名称 |
| 数量 | 本次真实采购数量或经批准的演示数量 |
| 采购单价 | 真实报价 |

6. 如需多个商品，点击“添加采购商品”，重复填写。
7. 点击“创建草稿”。
8. 预期结果：页面提示“采购订单已创建，状态为草稿”，新采购单出现在列表顶部，状态为“草稿”。

如果供应商下拉框为空，返回“采购与供应商”页面先创建供应商。

### 5.3 审批采购订单

1. 在草稿采购单对应行点击“审批”。
2. 确认框显示“审批后采购单将进入可下单状态，但不会自动向供应商付款或下单。”
3. 点击“确认审批”。
4. 预期结果：状态由“草稿”变为“已审批”，操作列出现“下单”和“取消”。

### 5.4 完成真实下单后更新状态

1. 在“已审批”采购单对应行点击“下单”。
2. 在真正点击确认前，必须先确认已经在 1688 或供应商渠道完成真实下单。
3. 确认框显示“请先在 1688 或供应商渠道完成真实下单，再确认此动作。”
4. 点击“确认已下单”。
5. 预期结果：状态由“已审批”变为“已下单”，操作列出现“分批收货”和“确认收货”。

如果只是页面演示、尚未产生真实采购承诺，不要点击“确认已下单”。

### 5.5 登记收货

分批到货：

1. 第一批真实到货后，在“已下单”采购单点击“分批收货”。
2. 点击“确认部分收货”。
3. 预期结果：状态变为“部分收货”。

全部到货：

1. 在“已下单”或“部分收货”采购单点击“确认收货”。
2. 确认框显示“确认采购商品已全部到货后，采购单将结束收货流程。”
3. 点击“确认全部收货”。
4. 预期结果：状态变为“已收货”，操作列显示“已结束”。

采购收货完成后，如需要更新可售库存，继续前往“WMS 库存仓储”按实际入库单或盘点流程确认，不能把采购单已收货直接当成库存可用。

## 8. 停止条件

出现以下任一情况时必须停止演示：

1. 登录失败或权限不足。
2. 1688 链接无法访问，且没有有效的备用链接或手工录入数据。
3. AI 分析失败但页面没有明确成功结果。
4. 商品缺少名称、采购成本等必要数据。
5. 候选状态按钮与当前状态不匹配。
6. 采购页没有“新建采购单”。
7. 供应商下拉框为空。
8. 采购状态流转按钮与当前状态不匹配。
9. 页面出现 `401`、`403`、`500` 或明确的接口失败提示。
10. 现场负责人尚未确认真实下单或真实收货。

停止后只需要输出：

```text
已停止在：页面名称
当前看到：页面实际文字
无法继续的原因：客观原因
需要的处理：负责人需要完成的动作
```

不得继续猜测，不得描述未发生的成功结果。
