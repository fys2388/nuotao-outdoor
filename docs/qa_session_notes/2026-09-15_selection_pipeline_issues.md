## 1. 问题记录（按发生顺序追加）

### P0-001 牛顿找品异步任务无轮询，立即显示"未找到"
- 现象：提交关键词「户外露营灯 充电式 便携 轻量化」+ 价 10-60 + MOQ 50，按钮从"AI找品中..."恢复为"开始找品"后，页面直接显示"推荐商品 0 个 / 未找到符合条件的商品"，但 AI 选品总结文案是"工作流已启动，正在为您搜索...请稍候"。
- 矛盾点：文案说"正在搜索"，列表却已经判定为 0 个；任务ID 10c2f9d8… 已生成，说明后端任务确实在跑。
- 影响：用户会误以为真的没找到，无法知道要等多久、去哪看结果。
- 建议：异步任务期间应保持 loading 骨架屏，按任务ID轮询或 SSE/WebSocket 推送结果；不要在任务未完成时给出"未找到"结论。

### P0-002 刷新页面后上次找品任务结果丢失
- 现象：首次找品任务（任务ID 10c2f9d8…）提交后刷新页面，输入框被清空、推荐商品列表消失，无法从 UI 恢复/查看该任务的结果。
- 影响：用户一旦误刷新或重进页面，异步成果丢失；任务ID 也没有"查看历史任务/结果"入口。
- 建议：按当前用户保留最近 N 次找品任务记录（任务ID、关键词、时间、结果快照），可回看与重试。

### P0-003 牛顿找品耗时 48s 才返回，前端无明确进度指示
- 现象：第二次用短关键词「露营灯」+ 价 5-100 + MOQ 10，按钮在 ~2s 后即恢复为"开始找品"，但真实结果约 48s 后才渲染出来。期间页面既无进度条也无"等待中"提示，和 P0-001 是同一类问题：前端轮询/推送缺失。
- 实测：第一次长关键词 36s 时前端误判"未找到"；第二次短关键词 48s 才真正出 3 个结果。

### P1-004 带入工作流后 description 被错误预填为牛顿推荐语
- 现象：点击第一个商品"带入工作流编辑"跳转到 /products/pipeline，name/price 正确，但 description 被填成"牛顿AI按性价比排序推荐（210+）"——这是牛顿对话里的推荐话术，不是产品描述。
- 影响：如果不人工改，后续 AI 分析/生图 Prompt 会把这句话当产品描述，污染下游所有产物。
- 建议：带入工作流时应映射 1688 商品详情描述，而不是把对话总结塞到 description 字段。

### P2-005 表单 placeholder 残留水杯类目示例文案
- 现象：core_selling_points / usage_scenarios / product_features 三个多行输入框的 placeholder 分别是"便携易带/一杯刚刚好/拆洗方便"、"办公室/健身房/户外"、"USB充电/300ml容量/食品级材质"——明显是水杯类目的示例，与当前露营灯产品完全不符。
- 影响：运营看着 placeholder 容易以为是系统预填值，或被误导往水杯方向写。
- 建议：placeholder 应根据当前商品类目动态切换，或改为中性提示"每行一个卖点"。

### P2-006 1688采购价字段带货币符号
- 现象：price 字段值为"¥6.7"而不是纯数字 6.7。
- 影响：后续做成本计算、汇率换算、利润模型时需要先去符号；如果有人直接 parse float 会 NaN。
- 建议：存储层用 Decimal 纯数字，UI 显示层再加 ¥/$ 前缀。

### P0-007 工作流 8 秒跑完 4 个 AI 步骤，主图生产变体数为 0
- 现象：点击"一键运行"后总耗时 8.02 秒，工作流进度显示 5/6 步 completed（商品信息/AI产品分析/主图生产/生图Prompt/上架数据），但切到"主图生产"标签，实际显示"变体数量：0"。
- 影响：步骤状态与真实产物严重不符；运营会以为主图已生成，实际一张图都没有。
- 建议：步骤完成判定必须以真实产物数量为准（主图 N 张、变体 M 个）；为 0 时应标记 failed/skipped 并说明原因。

### P1-008 点击"一键生图"接口返回 ok 但 UI 无任何反馈
- 现象：点击"一键生图"按钮，Network 可见 `POST /api/v1/image-gen/generate` 返回 200，但页面无 loading、无图片、无 toast、无错误提示。等待 60 秒仍无图。
- 影响：运营不知道生图是否在跑、跑到哪、结果在哪；接口可能成功但前端没渲染，也可能业务上失败被吞。
- 建议：生图走异步任务（任务ID + 轮询/SSE），前端展示任务状态与进度条；失败必须有 toast 或错误条。

### P1-009 "发送到生图工作台"按钮是半成品
- 现象：点击后 URL hash 变为 `#/image-studio`，但页面内容未切换；直接访问 `/image-studio` 返回"页面不存在"。
- 影响：按钮存在但功能未接通，用户点了像死按钮。
- 建议：要么接通生图工作台路由并带上当前 SKU 上下文，要么先隐藏该按钮并标注"开发中"。

### P2-010 上架数据标签被截断到 ~10 个字符
- 现象：上架数据预览里"标签"一列显示："复古高颜值设计，瞬间, 3种照明模式，一键切, USB可充电设计，环, 户外露营帐篷照明, 后院聚会氛围营造"——每条标签都被切到约 10 个字符（"瞬间"后面没了），明显是 CSS max-width + ellipsis 把每个 tag 截断了。
- 影响：标签入库可能也是截断值，影响 WooCommerce 端搜索与过滤。
- 建议：检查 tags 生成接口返回与前端渲染两层，确认入库的是完整标签还是截断值。

### P2-011 pipeline 页面刷新后历史结果丢失
- 现象：一键运行完成、生成上架数据预览后，刷新 /products/pipeline 页面，左侧表单清空、工作流进度回到"请在左侧输入商品信息并点击'一键运行'"，右侧历史记录里那条 SKU=NT-VINTAGEGLO-09150731 也不见了。
- 影响：和 P0-002 同源——异步/中间结果无持久化视图；运营刷新就丢工作。
- 建议：历史记录列表应从后端拉取该用户最近 N 次 pipeline run，可点击恢复现场。

### P0-012 面向 US 市场的上架数据全是中文（未做语言本地化）
- 现象：目标市场=US，WooCommerce 店铺面向海外客户，但一键运行后生成的上架数据预览：
  - 商品名称：「VintageGlow 复古露营灯 户外多功能马灯 USB充电帐篷灯 家用应急手提灯」（中英混排）
  - 短描述：「跨境复古露营灯户外氛围灯 多功能野营帐篷灯…」（全中文）
  - 完整描述：「VintageGlow复古露营灯，将怀旧美学与户外实用完美融合…」（全中文）
  - 标签：「复古高颜值设计，瞬间, 一灯多用：手提、悬挂, USB充电+大容量电…」（全中文，且每条被截断）
- 影响：直接违反项目规范"上传电商产品必须全英文"；美区客户看到全中文商品页，转化为 0。
- 建议：上架数据阶段必须按 target_market=US 强制输出英文（商品名/短描述/长描述/标签/SEO）；中文只能作为内部候选名，不进 WooCommerce。生成后应有语言校验（非英文比例 > 阈值直接拦下）。

### P1-013 1688 一键导入耗时 42 秒，期间无任何 loading 反馈
- 现象：在 pipeline 页面粘贴 1688 URL 点"导入"，42 秒后才把 name/price 填进表单；期间按钮无 loading、无进度、无禁用态。
- 影响：运营会以为点了没反应，反复点击或以为失败。
- 建议：导入按钮应立即 disabled + 转圈，前端轮询导入任务状态。

### P2-014 1688 导入字段映射简陋
- 现象：导入后 name=商品标题、description=商品标题（直接复用，没抓详情页正文）、price="6.7-19.7"（区间字符串，非数字）、category 空、卖点/场景/功能全空。
- 影响：等于只做了半次抓取，下游 AI 还要重新猜。
- 建议：导入阶段应抓详情页正文作为 description，price 取区间最低价 + 记录最高价；category 自动映射到 WooCommerce 分类树。

### P1-015 点"保存为草稿"接口 200 但 UI 不更新
- 现象：确认上架弹窗点"保存为草稿"，Network 可见 `POST /api/v1/product-pipeline/confirm-list` 返回 200，但弹窗不关闭、工作流进度仍 5/6、"上架WC"仍 pending_confirmation、无成功 toast。
- 影响：运营不知道到底上没上；重复点击可能创建重复商品。
- 建议：确认接口返回后必须关闭弹窗、刷新工作流进度到 6/6、弹成功 toast 并给出 WooCommerce 草稿编辑链接。

### P1-016 confirm-list 接口 200 但商品未真正落库
- 现象：点"保存为草稿"后，去 /products/listing 商品列表，刷新后仍只有原来 5 条，新草稿 SKU=NT-VINTAGEGLO-09150738 未出现。
- 影响：接口成功但数据没进商品主数据库；可能写到 WooCommerce 草稿但本地主数据没同步，也可能两边都没写。
- 建议：confirm-list 必须本地事务写主数据 + 调 WC 草稿，两步都成功才算完成；失败要回滚并报错。

### P1-017 批量导入错误信息直接暴露后端技术栈与 ACL 错误
- 现象：无效链接 `offer/000000000000.html` 的失败原因显示：「牛顿 Agent 返回结果无法解析: Newton Agent did not return a product title（开放平台：gw.APIACLDecline: AppKey is not allowed(acl)）」。
- 问题：
  1. 直接把阿里开放平台原始错误 `gw.APIACLDecline: AppKey is not allowed(acl)` 抛给运营，泄露后端集成细节；
  2. 根因是 AppKey 无权限，但前端文案却说"返回结果无法解析 / did not return a product title"，误导运营以为是商品页问题；
  3. 真正问题是牛顿 API AppKey 的 ACL 配额/权限配置，应该是 ERROR 级告警给管理员，而不是显示给运营。
- 建议：错误分类——网络/鉴权/商品不存在/解析失败分别映射为对运营友好的中文文案；鉴权类错误走告警通道，不在业务页暴露。

### P2-018 批量导入进度百分比与完成数不一致
- 现象：导入结果区显示"2/4 成功 2 失败 1 分析中"，顶部进度条却显示 75%。2/4=50%，3/4=75%，对不上。
- 建议：进度百分比按已完成（成功+失败）/总数计算，或按成功/总数计算，口径统一。

### P2-019 批量列表里同一链接重复显示两行
- 现象：第一个链接 `offer/670686829577.html` 在导入结果列表里出现了两行（一行"分析中"、一行"已完成 跨境新款露营灯超长续航…牛顿 Agent"——但这一行标题其实是第二个链接的商品名）。
- 怀疑：行与链接的绑定错位，或者是之前 pipeline 跑过的同 SKU 被重复拉取后未去重。
- 建议：导入结果按 offer_id 去重；每行的"链接/状态/商品名"严格对应。

### P1-020 批量导入某任务卡死在"分析中"无超时
- 现象：第一个链接 `670686829577` 提交后卡在"分析中"超过 95 秒，状态不更新、不报错、不自动失败；"重试"按钮 disabled。
- 怀疑：该 offer_id 之前在 pipeline 跑过，重复导入触发了某种锁或幂等冲突。
- 建议：单条导入任务必须有超时（建议 60-90s），超时自动标记 failed 并允许单独重试；重复 offer_id 应直接返回已有结果而不是再入队。

### P1-021 批量"已完成"但下游三个结果 tab 全空
- 现象：导入结果列表显示 2 个商品"已完成"，但右侧"AI 识别结果 / 产品信息报告 / 生成 Prompt"三个 tab 全部停留在引导空态："导入商品后显示 AI 识别结果"、"完成 AI 分析后生成产品报告"、"完成产品报告后生成生图 Prompt"。
- 影响：前端显示"已完成"只是 1688 抓取完成，10 字段识别 / 17 字段报告 / 生图 Prompt 实际未触发或未回显；运营以为跑完了，点进去全是空。
- 建议："已完成"必须是端到端完成（抓取+识别+报告+Prompt），否则应拆成"抓取完成 / 识别中 / 报告中"多个状态。

## 2. 总结与优先级建议

### 本次实测路径
- **方式一（关键词模糊）**：牛顿 AI 对话选品 → 关键词「露营灯」+ 价 5-100 + MOQ 10 → 48s 返回 3 款推荐 → 点"带入工作流编辑"进入 /products/pipeline → 修正脏预填 → 一键运行 8-9s → 上架数据预览（中文）→ 确认上架 → 保存为草稿。
- **方式二（批量外部链接）**：/products/analysis → 粘贴 4 个 1688 链接（3 真 1 假）→ 批量导入 → 2 成功 1 失败 1 卡死。
- **上架动作**：pipeline 内"确认上架 → 保存为草稿"，接口 200 但本地商品主数据未出现新草稿。

### 必须优先修（P0，阻塞业务）
1. **P0-012 上架数据全中文**：面向 US 市场的 WooCommerce 商品名/描述/标签全中文，直接违反"全英文"硬规范。需要在"上架数据"步骤强制按 target_market 输出英文 + 语言校验。
2. **P0-007 主图生产 completed 但变体数 0**：步骤状态与真实产物不符；8 秒跑完 4 个 AI 步骤疑似走了 mock/缓存。
3. **P0-001/P0-003 异步任务无轮询**：牛顿找品、批量导入都靠"碰运气等"，前端没有进度推送；第一次长关键词被误判"未找到"。

### 应该尽快修（P1，影响可用性）
- P1-008 一键生图接口 200 但 UI 无图无反馈
- P1-009 发送到生图工作台按钮是死链（404）
- P1-015/P1-016 保存为草稿接口 200 但弹窗不关、商品没落库
- P1-017 错误信息直接暴露 `gw.APIACLDecline` 后端技术栈
- P1-020 批量任务卡死"分析中"无超时
- P1-021 批量"已完成"但下游 3 个 tab 全空
- P1-013 1688 导入 42s 无 loading

### 可排期修（P2，体验/数据质量）
- P0-002/P2-011 页面刷新丢任务、丢历史
- P2-005/P2-022 表单 placeholder 残留水杯类目示例（"便携榨汁杯""一杯刚刚好""300ml容量"）
- P2-006/P2-014 price 带 ¥/区间字符串，需要纯数字
- P2-010/P2-023 标签被截断到 ~10 字符
- P2-018 进度百分比 2/4 显示 75%
- P2-019 同一链接在结果列表重复显示两行
- P1-004 description 被预填成牛顿推荐语
- P2-014 1688 导入只抓了标题，描述/类目/卖点全空

### 建议下一步
1. 先把 P0-012 英文输出和 P0-007 主图真实生成打通——这是选品到上架能否真正跑通的核心。
2. 异步任务统一加"任务ID + 轮询/SSE + 超时 + 结果持久化"，消灭 P0-001/P0-003/P1-013/P1-020 一类问题。
3. 上架动作补"本地主数据 + WooCommerce 草稿"双写事务和 UI 状态回写（P1-015/P1-016）。
4. 把 Newton API 的错误分级包装，不要把 `gw.*` 原始错误抛给运营（P1-017）。
