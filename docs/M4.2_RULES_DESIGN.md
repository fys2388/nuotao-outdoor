# M4.2 Supply Chain Agent — 规则设计（Rules Design）

> 版本：v1.0
> 日期：2026-11-21
> 阶段：M4.2 第一阶段（现状审计 + 架构设计，不含代码实施）
> 决策身份：ChatGPT Owner
> 执行身份：DSH（执行 Agent）
> 上游依据：`M4.2_AGENT_DESIGN.md`、`docs/AGENTS.md` §1.2/§3.3、`services/rule_engine.py` + `models/rule.py`
> 核心铁律：**规则存库不硬编码；AI 只能读取评估规则，绝不自动修改**

---

## 1. 规则设计原则

| # | 原则 | 落地 |
|---|---|---|
| R-1 | **规则入库存，不硬编码** | 所有供应链业务规则存 `rules` 表（对齐 AGENTS.md §1.2「禁止硬编码业务经验值到业务逻辑」），由 `rule_engine` 评估 |
| R-2 | **AI 只读评估** | Supply Chain Agent 经 `rule_engine.check()/evaluate()/suggest()` **读取评估**规则；`override()` **只审计不执行**且标注 `approval_level` 待人工 |
| R-3 | **硬规则 gate 动作** | `rule_type="hard"` 规则用 `check()` 阻断违规动作；不通过则 Agent 不得产出相应建议 |
| R-4 | **软规则加权打分** | `rule_type="soft"` 规则用 `suggest()` 加权聚合，产出评分/优先级（如采购建议优先级） |
| R-5 | **版本化 + 生效窗** | 规则变更走 `create_rule`（draft→active，新版本），`_load_rules` 只取 active + 最新版本 + 时间窗生效 |
| R-6 | **每次评估留审计** | `rule_engine` 每次评估/覆盖写 `rule_execution_logs`（`rule_id`/`rule_version`/`context`/`result`/`trace_id`） |
| R-7 | **校准仅提议** | 学习闭环的规则校准（`supply_chain_calibration_runs`）**永不自动应用**；回写须经人工审批 + 版本化 + 审计 |
| R-8 | **分类隔离** | 供应链规则 `category="supply_chain"`（可细分 `supply_chain.procurement`/`inventory`/`supplier`/`cost`），与 product/marketing 域规则隔离 |

---

## 2. 规则分类体系

| rule_type | 用途 | 执行方式 | 供应链示例 |
|---|---|---|---|
| `hard` | 硬性业务约束，**gate 动作** | `check()` → `all_passed` 布尔 | 最小起订量、成本上限、供应商黑名单、成本确认门、禁止外发下单 |
| `soft` | 优先级/评分，**加权打分** | `suggest()` → `aggregate_score` | 采购优先级、供应商偏好、风险加权 |
| `flow` | 流程编排条件 | `evaluate()` → 分支 | 补货触发条件、海外仓切换条件 |

`approval_level`：标注规则覆盖/变更所需的审批级别（L0-L3），Agent 层据此接线审批。

## 3. 供应链硬规则清单（`rule_type="hard"`）

以下为 M4.2 需注册的硬规则（**种子清单**，实施阶段入库）。每条规则体现 Owner 不可突破约束。

### 3.1 `SC_MIN_ORDER_QTY` — 最小起订量（MOQ）门

```json
{
  "rule_id": "SC_MIN_ORDER_QTY",
  "name": "采购量须满足供应商 MOQ",
  "category": "supply_chain.procurement",
  "rule_type": "hard",
  "when_conditions": {
    "and": [
      {"field": "recommendation.recommended_quantity", "op": "lt", "value_ref": "supplier.moq"}
    ]
  },
  "then_result": {
    "passed_message": "采购量满足 MOQ",
    "failed_message": "采购量低于供应商 MOQ，须调整或更换供应商"

  "params": {},

}
```

## 4. 供应链软规则清单（`rule_type="soft"`，加权打分）

软规则用于采购建议**优先级/评分**聚合，经 `suggest()` 输出 `aggregate_score`。

| rule_id | 名称 | 维度 | params（权重/阈值） |
|---|---|---|---|
| `SC_SUPPLIER_ON_TIME_WEIGHT` | 供应商准时率加权 | 供应商绩效 | `{"weight": 0.25, "threshold": 0.9}` |
| `SC_SUPPLIER_QUALITY_WEIGHT` | 供应商质量加权 | 供应商绩效 | `{"weight": 0.25, "threshold": 0.95}` |
| `SC_SUPPLIER_RISK_PENALTY` | 高风险供应商降权 | 风险 | `{"penalty_high": 0.3, "penalty_medium": 0.1}` |
| `SC_PRICE_COMPETITIVENESS` | 价格竞争力加权 | 成本 | `{"weight": 0.2}` |
| `SC_LEAD_TIME_WEIGHT` | 交期加权 | 履约 | `{"weight": 0.15, "preferred_days": 14}` |
| `SC_DEMAND_SIGNAL_WEIGHT` | 需求信号加权 | 需求预测 | `{"weight": 0.15, "min_confidence": 0.6}` |

> 软规则权重本身**不可被 AI 自动调整**；校准提案（经学习闭环）**仅提议**新权重，人工审批后经版本化回写（对齐 Product Analyst `run_calibration` 的「SCORE_WEIGHTS/rules are never modified automatically」）。

## 5. 规则与 Agent 的执行边界

```mermaid
flowchart LR
    SC[Supply Chain Agent] -->|check() 硬规则| GATE{all_passed?}
    GATE -->|是| SUG[产出建议]
    GATE -->|否| BLOCK[阻断，不产出建议 + 记录 failed_message]
    SC -->|suggest() 软规则| SCORE[加权评分 → 优先级]
    SC -.读取评估.-> RE[rule_engine]
    RE --> RUL[rules 表 active 最新版本]
    SC -.override().-> RE
    RE -->|只审计不执行| LOG[rule_execution_logs]
    CAL[supply_chain_calibration_runs] -->|仅提议| HUMAN[人工审批]
    HUMAN -->|approved| WB[版本化回写 rules/profiles + 审计]
```

**关键边界**：
1. **硬规则 check 不通过 → Agent 不得产出该建议**（gate）。
2. **软规则 suggest → 评分/优先级**，供 Agent 排序建议。
3. **AI 对规则只有读取评估权**；`override()` 只审计不执行。
4. **规则校准（学习闭环）仅提议**，人工审批后经版本化回写（走 `StrategyVersion` 或 `create_rule` 新版本），回写本身留 `event_log` + `rule_execution_logs` 审计。

## 6. 规则版本化与生效

| 机制 | 说明 |
|---|---|
| 唯一性 | `(workspace, rule_id, version)` 唯一 |
| 状态机 | `draft` → `active` → `deprecated` |
| 生效窗 | `effective_from` / `effective_to`；`_is_effective` 判时间窗 |
| 取最新 | `_dedupe_latest` 取同 rule_id 最新版本 |
| 变更 | 走 `create_rule` 新建版本行（不改历史），旧的标 deprecated |
| 审计 | 每次评估写 `rule_execution_logs`（含 `rule_version`）；规则变更走 `StrategyVersion` 或 `event_log` |

## 7. 规则种子与初始化

| 项 | 策略 |
|---|---|
| 种子函数 | `ensure_supply_chain_rules()`（幂等，对齐 `agent_seed.py` 模式），播种 §3 硬规则 + §4 软规则 |
| 首次播种 | 按 `get_settings()` 播种默认（对齐 `agent_policies` 模式） |
| 幂等 | 已存在同 `(rule_id, version)` 则跳过 |
| 审批级别 | 硬规则默认 `approval_level="L0"`（不可被 Agent 覆盖）；如需人工覆盖接线到审批层 |
| **本轮不执行** | 种子函数与规则入库属代码实施，Owner 审批后才编写 |
