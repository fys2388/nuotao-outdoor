# Nuotao AI OS - 多环境配置指南

## 环境概览

| 环境 | 配置文件 | 用途 | 调试模式 | 日志级别 | 数据 |
|------|----------|------|----------|----------|------|
| 开发 (dev) | `.env.development` | 本地开发、调试、单元测试 | ✅ true | DEBUG | 本地测试数据 |
| 预发布 (staging) | `.env.staging` | 上线前测试、UAT验收、集成测试 | ❌ false | INFO | 隔离测试数据 |
| 生产 (prod) | `.env.production` | 正式生产环境、真实业务数据 | ❌ false | WARNING | 真实生产数据 |

## 快速切换

### Windows
```bash
# 查看当前环境
switch-env.bat

# 切换到开发环境
switch-env.bat dev

# 切换到预发布环境
switch-env.bat staging

# 切换到生产环境（需要确认）
switch-env.bat prod
```

### Linux/Mac
```bash
# 切换环境
cp .env.development .env    # 开发
cp .env.staging .env        # 预发布
cp .env.production .env     # 生产
```

## 密钥管理规范

### 开发环境
- 可以使用开发密钥（已在配置文件中）
- 禁止提交真实生产密钥到代码库

### 预发布环境
- 所有 `CHANGE_ME` 必须替换为真实值
- 使用独立的测试账号和密钥
- 禁止使用生产数据

### 生产环境
- 所有 `CHANGE_ME` 必须替换为强随机值
- 密钥使用 Secrets 管理（不写入文件）
- 数据库密码至少 32 位随机字符
- JWT 密钥至少 64 位随机字符
- 定期轮换密钥（建议每 90 天）

## 环境切换检查清单

切换到新环境后，必须验证：

- [ ] `.env` 文件已正确复制
- [ ] 数据库连接正常（`SELECT 1`）
- [ ] Redis 连接正常（`PING`）
- [ ] 后端服务启动成功（`/health` 端点）
- [ ] 前端页面可访问
- [ ] WooCommerce API 连接正常
- [ ] LLM API 调用成功（测试一次）
- [ ] 飞书通知发送成功（测试一次）
- [ ] 日志输出正确（级别、格式）
- [ ] 备份任务已配置

## 常见问题

### Q: 切换环境后服务无法启动？
A: 检查 `.env` 文件中的数据库连接信息是否正确，确保目标数据库已创建且可访问。

### Q: 如何验证当前运行的环境？
A: 访问 `GET /api/v1/health` 端点，返回的 `environment` 字段即为当前环境。

### Q: 可以同时运行多个环境吗？
A: 可以，但需要使用不同的端口和数据库。建议使用 Docker Compose 管理多环境。

### Q: 生产环境密钥如何安全管理？
A: 使用云服务商的 Secrets Manager（如 AWS Secrets Manager、阿里云 KMS），或使用 `.env.local` 文件（不提交到 Git）。
