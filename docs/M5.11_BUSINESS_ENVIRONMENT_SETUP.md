## 1. DATABASE_URL 配置方式

变量：

```text
DATABASE_URL=postgresql+asyncpg://<USER>:<PASSWORD>@<HOST>:<PORT>/<DBNAME>
```

要求：

- 指向**真实 PostgreSQL 16**（生产/专用 staging 实例），显式填写主机、端口、账号、库名。
- 禁止沿用配置默认值 `postgresql+asyncpg://<USER>:<PASSWORD>@localhost:5432/<DBNAME>`。
- 数据库账号按最小权限拆分：应用账号只拥有业务库读写，不拥有超级用户权限。

注入方式（二选一）：

1. 进程环境变量：

   ```powershell
   # PowerShell
   $env:DATABASE_URL = "postgresql+asyncpg://<USER>:<PASSWORD>@<HOST>:<PORT>/<DBNAME>"
   ```

   ```bash
   # bash / Linux staging
   export DATABASE_URL="postgresql+asyncpg://<USER>:<PASSWORD>@<HOST>:<PORT>/<DBNAME>"
   ```

2. `backend/.env` 文件（已被 `app/core/config.py` 读取，见 `.env.example` 模板）：

   ```text
   DATABASE_URL=postgresql+asyncpg://<USER>:<PASSWORD>@<HOST>:<PORT>/<DBNAME>
   ```

验证：

```powershell
cd backend
.venv\Scripts\python -m alembic current   # 期望输出 0022
.venv\Scripts\python -m alembic upgrade head   # 首次启动时执行
```


配套（可选，按需覆盖默认值）：

- `activation_gate` 会做**真实只读调用**（`GET {base}/models`）验证 key 有效性：

  - 认证错误（401/403）→ `FAILED`

注入方式同第 1 节（`backend/.env` 或进程环境变量），key 绝不落库、绝不打印。

## 4. WooCommerce 三件套配置方式

变量（三件套必须完整）：

```text
WOOCOMMERCE_BASE_URL=
WOOCOMMERCE_CONSUMER_KEY=
WOOCOMMERCE_CONSUMER_SECRET=
```

说明：

- `WOOCOMMERCE_BASE_URL`：自托管 WooCommerce 站点根地址（HTTPS）。
- `WOOCOMMERCE_CONSUMER_KEY` / `WOOCOMMERCE_CONSUMER_SECRET`：WooCommerce REST API 只读应用凭据（在 WooCommerce 后台「Advanced → REST API」创建，权限仅勾选 read）。
- 这三个变量当前由 `activation_gate` 直接从**进程环境变量**读取做只读可达性验证；`WooCommerceConnector`（`app/integrations/woocommerce.py`）同步时通过 source config 传入三件套。
- 只允许 `GET products / GET orders / GET customers`；禁止 POST / PUT / DELETE / 修改商品 / 创建订单 / 任何商业写动作。

注入方式：

```powershell
$env:WOOCOMMERCE_BASE_URL = "https://<shop-domain>"
$env:WOOCOMMERCE_CONSUMER_KEY = "<consumer-key>"
$env:WOOCOMMERCE_CONSUMER_SECRET = "<consumer-secret>"
```

（或写入 Secret Store，由进程注入；`.env.example` 只保留变量名占位。）

## 5. ACTOR_PROVIDER=header 配置方式

变量：

```text
ACTOR_PROVIDER=header
ACTOR_HEADER_NAME=X-Actor
```

说明：

- 代码扩展点：`app/core/actor.py`。
- `ACTOR_PROVIDER=body` 是当前默认（staging-safe），但被 `activation_gate` 判为 `BLOCKED_REAL_OPERATOR`（AUTHENTICATION_GAP：actor 由请求体声明，不视为真实身份）。
- 切换 `header` 后，approval/experiment/audit 的 actor 由请求头（默认 `X-Actor`）提供，服务端 `resolve_actor()` 校验：
  - 非空、长度 ≤ 64、安全字符集 `[A-Za-z0-9_.@+-]`
  - 禁止保留身份 `agent` / `system`
- 生产要求：身份头必须由真实 SSO/JWT 网关注入；若 header 缺失，服务端应拒绝（不要依赖 body 回退）。

---

## 6. SSO/JWT actor identity 要求

- actor（身份标识）、workspace、role、permission 全部由**服务端**决定，客户端禁止自声明 `admin` / `operator`。
- 接入方式：真实 SSO/JWT 网关（或反向代理）在请求中注入已验证身份头（`X-Actor`），后端按头解析。
- 校验链：`resolve_actor()` → workspace 隔离（`X-Workspace-Id` 头/服务端路由）→ `approval_rbac.check_approval_permission()`（403）。
- Agent actor 永远不能 approve / reject / start experiment：服务端对 `agent` / `system` 保留身份一律 403。
- 每个审批动作必须落审计：`actor` + `action` + `note` + `trace_id` + `timestamp`（`event_log`）。

## 7. RBAC Role：product.decision.approve / product.decision.reject

角色存放在 `agent_approval_roles` 表（workspace 隔离，`workspace_id` + `role_name` 唯一）。

创建（或替换）真实 operator 角色：

```http
POST /api/v1/approval-roles
X-Workspace-Id: <workspace_id>
Content-Type: application/json
```

```json
{
  "role_name": "product-operator",
  "permissions": [
    "product.decision.approve",
    "product.decision.reject"
  ],
  "actors": ["<REAL_OPERATOR_IDENTITY>"],
  "enabled": true
}
```

说明：

- `product.decision.approve`：批准 pending 产品决策（`POST /api/v1/product-decisions/{decision_id}/approve`）。
- `product.decision.reject`：驳回 pending 产品决策。
- 实验启动是独立人工闸门：`started_by` 必填且经 `resolve_actor()` 校验，Agent 启动一律 403，无需额外 permission 名。
- 列出/复核：

```http
GET /api/v1/approval-roles
```

- 校验：`activation_gate` 的 `rbac` 项会检查启用角色是否同时含这两个权限；缺失即 `BLOCKED`。

## 11. Real Product 查询方法

优先级（严格禁止 synthetic / fixture 冒充真实）：

1. **WooCommerce 只读查询**（真实业务产品源）：

   ```powershell
   # REST 直接查询（Basic auth = consumer key/secret，只读）
   curl -u "<CONSUMER_KEY>:<CONSUMER_SECRET>" `
     "<WOOCOMMERCE_BASE_URL>/wp-json/wc/v3/products?per_page=10&status=publish"
   ```

2. **经现有 Connector 同步**（只读）：

   ```http
   POST /api/v1/connectors/woocommerce/sync
   ```

   ```json
   {
     "connector_name": "woocommerce",
     "config": {
       "kind": "products",
       "base_url": "<WOOCOMMERCE_BASE_URL>",
       "consumer_key": "<CONSUMER_KEY>",
       "consumer_secret": "<CONSUMER_SECRET>"
     }
   }
   ```

3. **数据库复核**（仅查询，确认已同步产品）：

   ```sql
   SELECT id, sku, name, status, source
   FROM products
   WHERE workspace_id = '<WORKSPACE_ID>' AND status = 'active'
   ORDER BY created_at DESC;
   ```

输出只包含必要字段：`product_id`、`sku`、`name`、`source`。禁止输出 customer PII、credentials、订单敏感数据。

选出 1~3 个真实产品作为 Pilot Candidate；数量为 0 时保持 `BLOCKED_REAL_PRODUCT`。

## 13. Secret 安全要求

- API key / consumer secret / password / token / credentials 只允许来自环境变量或 Secret Store。
- 禁止写入：PostgreSQL、Redis、event_log、trace、agent_executions、console audit、应用日志。
- `activation_gate` / `readiness` 只检查「是否存在」，**永不输出值**。
- `backend/.env` 必须加入 `.gitignore`；`.env.example` 只放变量名与占位符，禁止真实值。
- `git status` / `git diff` 中不得出现任何 secret。
- 日志中禁止出现 PII（email / phone / address / card / cvv）；产品 context 只含业务字段，缺失字段标记 `UNKNOWN`。
- 若发现 secret 泄漏，立即轮换凭据并记录事件，禁止掩盖。

## 14. Production 禁止事项

- 开发第二个业务 Agent（Marketing / Customer / Supply Chain / Growth）。
- 自动 approve / reject / 自动 start experiment / 自动 calibration / 自动 knowledge sync。
- 自动 purchase / campaign / inventory allocation / refund / 任何商业动作。
- 修改 SCORE_WEIGHTS、rules、业务规则以「让测试通过」。
- fake API key、mock 冒充真实 LLM、synthetic product 冒充真实产品。
- fake actual_result、fake ROI（无 verified attribution source 时 `revenue_impact` / `margin_impact` / `roas_impact` 保持 `null`）。
- WooCommerce 写操作（POST/PUT/DELETE）。
- 用本地默认 PostgreSQL / Redis 冒充生产环境。
- 修改代码绕过 activation gate，或把 `BLOCKED` 改判为 `PASSED`。
