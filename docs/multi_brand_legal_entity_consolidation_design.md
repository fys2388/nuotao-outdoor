# 多品牌、多法人与内部交易合并设计

> 文档版本：v1.1  
> 状态：P2-7 / P2-8 首期已完成并验收  
> 迁移版本：`0046`  
> 适用范围：商品归因、B2C/B2B 交易归因、法人主体、品牌合并报表和内部交易收入消除

---

## 1. 需求与边界

同一工作区可能同时经营多个品牌，并由多个法人主体承接合同、收款和开票。经营报表不能简单把所有渠道收入相加，否则内部销售会被重复计算，也无法回答“利润来自哪个品牌、由哪个法人承担”。

首期解决：

- 维护品牌和法人主体。
- 商品归属品牌，品牌可配置默认法人。
- B2C 订单、B2B 订单和 B2B 发票形成可审计归因。
- 按品牌、法人、业务模式和币种生成合并报表。
- 内部交易先进入待审批状态，经管理员批准后消除内部收入。
- 未归因商品和未归因交易显式展示，不自动猜测。

首期不解决：

- 买方侧完整会计分录和集团法定合并报表。
- 内部交易利润的会计级消除。
- 税务口径合并、少数股东权益和抵销税影响。
- 外币报表折算差额。

因此当前页面和接口只能称为“管理会计首期合并视图”，不能替代审计后的法定合并报表。

## 2. 数据模型

### 2.1 法人主体

`legal_entities`：

- `workspace_id + code` 唯一。
- 保存国家、功能币种、状态、法定名称和创建人。
- 同一工作区可维护多个法人，查询始终限定工作区。

### 2.2 品牌

`brands`：

- `workspace_id + code` 唯一。
- 可绑定 `default_legal_entity_id`。
- 品牌和默认法人只用于归因建议，不替代每笔交易的人工确认。

### 2.3 商品品牌

`products.brand_id` 是自动归因的起点。同一订单中的商品品牌必须唯一，系统才会推断品牌和默认法人；混品牌订单返回未归因，等待人工登记。

### 2.4 交易归因

`commerce_attributions` 覆盖：

- `b2c_order`
- `b2b_order`
- `b2b_invoice`

归因保存品牌、法人、归因来源、内部交易对手方、消除状态、消除金额、证据、操作人和审批人。一个业务事实最多只有一条归因。

## 3. 自动归因规则

```text
B2C / B2B 订单
  -> 读取订单行商品
  -> 商品品牌集合长度为 1
  -> 使用商品品牌
  -> 使用品牌默认法人
  -> 写入 auto 归因

B2B 发票
  -> 优先复制 B2B 订单归因
  -> 未找到订单归因时按发票关联订单重新推断
```

以下情况不写入自动归因：

- 订单没有可匹配商品。
- 订单包含多个品牌。
- 品牌未配置默认法人。
- 商品尚未绑定品牌。

自动归因失败不阻断订单入库或发票创建，只记录 warning。报表将缺口显示为“未归因品牌”或“未归因法人”。

## 4. 内部交易消除

状态机：

```text
not_applicable
  -> external transaction

pending
  -> approved
  -> rejected

rejected / approved
  -> pending  (人工重新登记归因后)
```

规则：

- 只有 `is_intercompany = true` 的交易可以进入审批。
- 买卖双方必须属于不同法人。
- 审批金额必须大于零且不能超过来源订单或发票总额。
- 只有管理员可以批准或拒绝。
- 批准后，内部交易金额从外部收入中扣除。
- 未批准、拒绝或待审批金额继续计入外部收入。
- 应收余额只在发票归因同样批准消除后才扣减。

## 5. 报表口径

按品牌、法人、业务模式和币种分组：

```text
账面收入
  = 已纳入期间的 B2C 订单收入 + B2B 订单收入

内部交易
  = 已批准的内部交易金额

外部收入
  = 账面收入 - 内部交易

未结应收
  = 发票余额 - 已批准且与发票关联的内部交易金额

毛利
  = B2C profit_snapshot.contribution_margin
    或 B2B 订单行收入 - 可追溯 ProductCost
```

- 指定报告币种时使用工作区直接汇率。
- 缺少汇率时拒绝换算，不推测反向汇率。
- 未指定报告币种时按原币种分组。
- 多币种不能直接汇总 totals。
- 成本覆盖不足时毛利返回缺失或部分覆盖，不按收入比例估算。

## 6. API 与权限

| 能力 | API | 权限 |
|---|---|---|
| 品牌、法人读取 | `/api/v1/admin/consolidation/*` | 登录用户 |
| 品牌、法人维护 | `POST/PATCH /api/v1/admin/consolidation/*` | `operator` 以上 |
| 商品品牌绑定 | `POST /api/v1/admin/consolidation/products/{id}/brand` | `operator` 以上 |
| 手工交易归因 | `PUT /api/v1/admin/consolidation/attributions/*` | `operator` 以上 |
| 批准/拒绝内部消除 | `/approve-elimination`、`/reject-elimination` | `admin` |
| 合并报表 | `GET /api/v1/analytics/consolidation` | 登录用户 |

## 7. 前端入口

管理端路由：`/analytics/consolidation`

页面包括：

- 品牌与法人合并视图。
- 法人主体维护。
- 品牌维护。
- 交易归因登记与内部交易审批。
- 品牌、法人、报告币种和期间筛选。
- 归因完整度和成本覆盖度提示。

## 9. 后续迭代

### P2-8 商品品牌归因治理（已完成首期）

- 提供未绑定品牌商品清单和最多 200 项的批量绑定入口。
- 批量绑定只补空，不覆盖已有品牌；逐项返回 assigned、skipped、failed 原因。
- 提供未归因订单、发票、缺少默认法人和混品牌订单的工作台。
- 提供品牌编辑能力，运营可补齐默认销售法人。
- 对具备完整证据的历史交易执行一次性自动归因补全。
- 所有批量操作写审计事件，前端只显示后端真实结果。
