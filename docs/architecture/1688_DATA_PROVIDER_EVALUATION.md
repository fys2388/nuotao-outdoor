# 1688 商品数据源 Provider 评估

> D8-E P1 调研产出。对应指令：1688 长期数据接入方案调研。
> 调研日期：2026-11-20。基于本地仓库一手材料（docs/ 与 backend/ 下 1688/牛顿相关文档与代码）。
> 本文档为评估与设计，不含任何凭据明文。未经 Owner 批准不实施生产切换。

## 0. 结论速览

| 维度 | 结论 |
|---|---|
| **推荐主源（生产级）** | 1688 跨境寻源通 API（方案 ID 1697014160788），开通后作生产自动流转主源 |
| **过渡降级源** | 传统 1688 开放平台 API 的 `alibaba.product.simple.get`（唯一已订购可用，200 万次额度），需配 AppSecret + AccessToken |
| **AI 建议层（非生产硬依赖）** | 阿里牛顿 AI Agent（积分 2026-10-19 起停发 + 返回结构不稳，仅作找品建议，关键动作人审） |
| **严禁进生产自动流转** | Scrapling 爬虫（无授权/不可审计）；妙手跨境（其授权属自有 SaaS，不可借用，仅对标）；硬编码 fallback（PR#13 已加闸门） |
| **三大阻塞** | ① 凭证缺失（AppSecret + AccessToken）② 权限被拒（product.get 返回 `gw.APIACLDecline`）③ GMV 双门槛不达标（月 16 万 + 单次 0.5 元） |

**一句话**：代码框架已就绪，真正瓶颈是**商业门槛与凭证权限**，而非工程量。长期方向是摆脱"人工维护浏览器 Cookie"，迁往有正式授权、可审计的官方 API。

## 2. 费用评估

| 方案 | 直接费用 | 隐性成本/门槛 |
|---|---|---|
| 寻源通 | 免费开通、无调用费 | 月 GMV≥160,000 元 + 单次调用 GMV≥0.5 元（硬考核） |
| 传统 1688 API | 免费申请，按量计费（对比表述 5000 次/日免费） | 需 AppSecret+AccessToken；高频批量触发单次 GMV 门槛 |
| 牛顿 Agent | 免费积分制 | 积分停发风险；单次任务 53-114 秒的时间成本 |
| 妙手 | 付费 SaaS（价格未明） | 授权不可复用 |
| Scrapling | 工具免费 | 合规/法律风险成本最高 |

**单次调用 GMV≥0.5 元的含义**：月 GMV ÷ 月调用次数 ≥ 0.5。例：月调用 32 万次需月 GMV≥16 万才达标。**高频批量低客单采集天然不达标**——批量选品必须靠缓存压缩调用量。

## 3. 合规风险

1. **Scrapling 爬 1688 属灰色地带**：无授权、不可审计、违反平台数据使用条款。严禁进生产自动流转；仅人工调研，且须先过合规评审（AGENTS.md 4.4）。
2. **妙手授权不可借用**：其 API 授权属其自有 SaaS，"对标≠拥有"，Nuotao 须自行申请自用型授权。
3. **Mock 数据污染风险**：Mock 带 `source=mock` 标识，但若误入生产会污染选品/定价。生产环境必须强制关闭 Mock、校验 `source≠mock`。
4. **牛顿积分停发**：2026-10-19 起停发，存在政策性中断风险，不可作生产硬依赖。
5. **牛顿字段推断风险**：响应结构不固定、字段缺失靠推断补齐，补齐字段须打"待核实"标记，禁止直接当权威采购价。
6. **数据可信度陷阱**：`get_price_trend` 是 ±5% 模拟估算（非真实，不可用于成本/定价）；库存 `stock` 仅 mock 含、无独立库存 API。

## 5. 稳定性评估

- **寻源通**：高（官方长期支持、技术响应快）。
- **传统 API**：中（框架完整，但公共详情接口被拒，依赖 simple.get）。
- **牛顿**：中等偏低（Java SDK 为主、项目 Python 原生实现、响应多层嵌套需 `_deep_find`、常把商品以文本块嵌入自然语言需 `_extract_product_cards` 解析、单任务实测 53-114 秒）。
- **Scrapling**：低（依赖反爬对抗）。

## 6. 推荐方案

- **主源**：1688 跨境寻源通 API（方案 ID 1697014160788）。唯一兼具**正式授权 + 功能最完整 + 官方稳定 + 可审计**的生产级数据源，符合"生产数据红线"。
- **过渡降级**：已订购的 `alibaba.product.simple.get`（传统 API，需配 AppSecret+AccessToken），作开通寻源通前的真实数据通道。
- **AI 建议层**：牛顿 Agent 作智能找品补充，关键动作保留 Human-in-the-loop。
- **理由**：寻源通是唯一满足"正式授权+可审计"生产红线的源；牛顿因积分停发+结构不稳只能作建议层；传统 API 的 simple.get 是当前唯一已订购可用的真实通道。

## 7. 迁移成本

代码层迁移成本**低**——`sourcing_1688_service.py` 与 `newton_agent_service.py` 均已完整实现（AOP 签名/OAuth/Mock 降级/source 字段归一化），框架无需重构。实际成本集中在**非代码环节**：

1. 申请与合规（联系跨境小二 sicongwz 加白 + 企业资质 + 审核 1-3 工作日）
2. 凭证配置（AppSecret 必配、AccessToken 需 OAuth 并定期刷新）
3. GMV 门槛达标（月 GMV 提至 ≥16 万，需合并采购订单/提高单价/杜绝跳单，预计 1-3 个月缓冲期）
4. 生产加固（强制关闭 Mock + 校验 source≠mock + Redis 缓存压缩调用量）

**主要瓶颈是商业门槛与凭证，而非工程量。**

## 8. 实施路线图

### Phase 0 — 立即解除 Mock 阻塞（~1 周，P0）
- 获取并注入 `ALI1688_APP_SECRET`（当前缺失导致 `is_configured()=false` 长期跑 Mock）
- OAuth 授权获取 `ALI1688_ACCESS_TOKEN` 并建定期刷新机制
- 验证真实链路：配 .env 后调 `GET /sourcing/1688/search`，确认 source 非 mock
- 生产环境强制关闭 Mock、所有调用校验 `source≠mock`

### Phase 1 — 申请生产级数据源（1-3 周，含审核）
- 联系跨境小二（钉钉 sicongwz）申请寻源通/采购解决方案白名单，提交企业资质
- 明确按"买卖家自开发模式/采购解决方案"申请，避免误申
- 向小二确认权威限流数值（本地文档仅"5000 次/日"对比表述，非权威）
- 确认库存/价格是推送还是轮询（材料均未明确，已知 gap）

### Phase 2 — 过渡期双轨运行
- 以 `simple.get`（200 万次额度）作过渡真实详情源，绕过被拒的 product.get
- 牛顿定位"找品建议层"，关键采购动作人审；补齐字段打"待核实"
- 明确标注 `get_price_trend` 为 estimated，隔离于成本模型
- 引入 Redis 缓存+每日调用上限，应对单次 GMV≥0.5 元门槛

### Phase 3 — GMV 达标与切换生产主源（1-3 个月）
- 落地 GMV 达标三方法：合并采购订单、提高采购单价、杜绝跳单
- 月 GMV 连续 2 个月达标后，将寻源通设为生产自动流转主源
- 补齐寻源通下单/订单/物流接口封装（当前未实现）

## 附：关键阻塞清单（按优先级）

1. **凭证缺失**（最高）：`ALI1688_APP_SECRET` 缺失致长期跑 Mock；`ALI1688_ACCESS_TOKEN` 缺失使授权接口不可用。
2. **权限被拒**：`alibaba.product.get` 返回 `gw.APIACLDecline`（2026-10-06 控制台实证）；唯一已订购可用为 `simple.get`。
3. **GMV 双门槛**：月 16 万 + 单次 0.5 元，商业而非技术阻塞。
4. **寻源通未订购**：需人工加白+资质审核，短期难开通形成数据源空窗。
5. **牛顿积分停发**：2026-10-19 起，不可作生产硬依赖。
6. **功能缺口**：图片搜款、自动下单、订单查询、独立库存接口未实现。
7. **权威限流数值缺失**：需向官方/小二确认。

> 局限说明：本文档完全基于本地仓库一手材料。QPS/日调用量精确官方数值、库存/价格推送机制在材料中均未明确，已标为需向官方确认的 gap。
