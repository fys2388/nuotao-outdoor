## 1. 风险登记方法

| 字段 | 说明 |
|---|---|
| ID | `SC-RISK-###` |
| 类别 | 架构 / 治理 / 数据 / 技术 / 流程 / 安全 / 遗留 |
| 可能性 | 高 / 中 / 低 |
| 影响 | 高 / 中 / 低 |
| 等级 | 高（红）/ 中（黄）/ 低（绿） |
| 缓解 | 预防 + 检测 + 应急 |
| 状态 | 开放 / 缓解中 / 已缓解 / 接受 |

## 10. 风险缓解责任与节奏

| 角色 | 责任 |
|---|---|
| **Owner（ChatGPT）** | 审批设计；裁决高危风险处置；批准/否决上线；不得为进度降低安全门槛 |
| **DSH（执行 Agent）** | 实施缓解措施；编写负向/边界测试验证约束被阻断；每 PR 自检门禁；不擅自越权 |
| **持续** | 每子阶段 PR 复核本风险册；新增风险即登记；已缓解风险标状态 |

**缓解节奏**：
- M4.2.0 优先消除 🔴 高危治理风险（SC-RISK-002 漏洞封堵 + SC-RISK-001/003 结构化阻断验证）。
- 每个子阶段结束复核对应风险是否已缓解或需新增。
- 上线前 SC-RISK-040（无评测上线）必须已缓解（评测集 ≥20 + 回归通过）。

## 12. 一句话结论

M4.2 的核心风险集中在**治理**（AI 下单/改规则/绕审批——已通过「外发下单工具不存在 + 硬规则 gate + 权限 L2 + 强制审批 + 校准仅提议」结构化阻断）与**数据可信度**（需求预测数据不足/1688 未验证/预测≠实际——已通过「低置信降级不伪造 + 未验证数据门 + 成本置信度分级」缓解）。**唯一现状已存在的高危漏洞是 SC-RISK-002（`procurement_service.create_purchase_order` 绕审批直建 approved），须在 M4.2.0 立即封堵。** 所有 D8-E 遗留安全事项保留不降级。风险缓解贯穿「Docs Before Code → 先收口后扩展 → 评测先行 → 人审在环」。
