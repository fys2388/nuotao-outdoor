## 1. 测试目标

| # | 目标 |
|---|---|
| T-1 | 验证 M4.2 五大能力（供应商/成本/采购决策/库存履约/学习闭环）的**正确性** |
| T-2 | 验证 Agent 全链路（运行→建议→审批→执行→反馈→评测）**治理正确** |
| T-3 | 验证**不可突破约束**（AI 不得下单/改规则/伪造成本/发未审核商品）**被结构化阻断** |
| T-4 | 验证工具白名单 + L0-L3 权限 + 审批 RBAC **授权正确** |
| T-5 | 验证数据模型迁移（Alembic）**可往返、不破坏既有数据** |
| T-6 | 满足 AGENTS.md §3.4：Supply Chain Agent **评测集 ≥20 用例**，提示词/模型变更跑回归 |
| T-7 | 合并门禁：lint + 单测 + 集成测试 + 依赖扫描全绿（AGENTS.md §2.5） |

## 2. 测试策略与基座

| 层 | 工具 | 说明 |
|---|---|---|
| 单元测试 | pytest + 内存 SQLite（`sqlite+aiosqlite:///:memory:` + StaticPool） | 快速，覆盖服务/规则/引擎纯逻辑 |
| 集成测试 | pgserver（内嵌 PostgreSQL 16）+ 真实 Redis + Alembic 迁移 | 验证真实 PG 行为（Decimal 精度、JSONB、迁移往返） |

| 异步 | `pytest-asyncio`（`asyncio_mode="auto"`） | |

| 评测 | 固定评测集 JSON fixture（**禁止用真实用户数据**，AGENTS.md §2.5） | Agent 评测回归 |

## 3. 测试范围与用例矩阵

图例：每项均含**正向 / 负向 / 边界**三类用例（对齐 Owner「必须包含正向、负向、边界测试」）。

### 3.1 方向 A：供应商智能分析

| 用例 | 类型 | 断言 |
|---|---|---|
| 供应商风险评分卡聚合正确 | 正 | risk_score 综合质量/准时/不良/产能/价格稳定；confidence 在 0-1 |
| risk_level 由 risk_score 分桶一致 | 边界 | score 阈值边界（如 80/60/40）→ level 映射正确 |
| 无评估历史的新供应商 | 边界 | confidence 低、返回「数据不足」而非伪造高分 |
| 供应商比价排序正确 | 正 | 按 landed_cost/risk 综合，MOQ 满足的候选优先 |
| 报价过期（valid_until < now）候选 | 负/边界 | 过期报价降权或标注过期，不当作有效报价 |
| 黑名单/critical 风险供应商 | 负 | 硬规则 `SC_SUPPLIER_BLACKLIST` gate 阻断，不产出采购建议 |
| 跨工作区供应商 404 | 负 | 工作区隔离 |
| 报价历史 append-only | 正/边界 | 新报价新增行，不改历史 |

### 3.2 方向 B：采购成本智能核算

| 用例 | 类型 | 断言 |
|---|---|---|
| 落地成本拆解 + 毛利计算正确 | 正 | 各分项 + total_landed_cost + gross_margin |
| 成本置信度分级 | 正/边界 | 全匹配=KNOWN/HIGH；部分=ESTIMATED/MEDIUM；全缺=UNKNOWN/LOW |
| UNKNOWN 成本不得高置信结论 | **负** | UNKNOWN 返回降级警告，**禁止高置信盈利结论**（profit_engine） |
| 1688 未验证数据门 | **负** | 硬规则 `SC_NO_UNVERIFIED_COST` 阻断未验证数据当成交价 |
| 成本预测 vs 实际偏差计算 | 正 | variance/variance_pct/accuracy 正确 |
| 成本置信度 <0.5 的 estimate | 边界 | 标注 estimate，不得当 actual（PO cost_confidence 语义） |
| 实际运费/关税回灌校准 | 正 | shipment 实际成本回灌后 landed cost 校准 |
| 成本主表新增 source/confidence 字段 | 正 | 迁移后可读写，default 不破坏旧行 |

### 3.3 方向 C：采购决策辅助

| 用例 | 类型 | 断言 |
|---|---|---|
| 需求预测 → 采购量推荐 | 正 | 基于 demand_forecast + reorder_point + safety_stock |
| 再订货点/安全库存计算 | 正/边界 | days_of_supply、reorder_point 阈值边界 |
| 数据不足时需求预测降级 | **负/边界** | 低 confidence + 禁止伪造预测 |
| MOQ 硬规则 gate | **负** | 采购量 < MOQ → `SC_MIN_ORDER_QTY` 阻断 |
| 成本上限硬规则 gate | **负** | 落地成本超上限 → `SC_COST_CEILING` 阻断 |
| 安全库存硬规则 gate | **负** | 补货后 < 安全库存 → `SC_SAFETY_STOCK_RESPECT` 阻断 |
| 结构化采购决策记录完整 | 正 | 推荐供应商/采购量/目标价/MOQ匹配/预期到货/理由/规则快照 |
| **采购单永不直接 approved** | **负（关键）** | 经 M4.2 链路生成的采购单只能是 draft/pending_approval；**不得出现直接 approved**（收口 GAP D-1 治理漏洞） |
| 采购审批人审留痕 | 正 | approved_by/at 写入；二次审批 400 |
| 跨工作区决策 404 | 负 | 工作区隔离 |

### 3.4 方向 D：库存与履约预测

| 用例 | 类型 | 断言 |
|---|---|---|
| 库存变动历史 append-only | 正 | inbound/outbound/reserve 各记一行，quantity_after 正确 |
| 缺货风险预测 | 正/边界 | stockout_risk 概率、predicted_stockout_at |
| 承诺交期 vs 实际对账 | 正 | promised_delivery_at vs delivered_at 偏差 |
| 库存快照 upsert 不覆盖 movements | 边界 | snapshot 更新但 movements 保留历史 |
| 海外仓切换条件测算 | 正 | 中国直发 vs 海外仓成本/时效对比（P1，可延后） |
| 非法 location | 负 | 422（cn/us/eu 之外） |

### 3.5 方向 E：供应链学习闭环

| 用例 | 类型 | 断言 |
|---|---|---|
| 供应商/物流评估分类正确 | 正 | success/failure/error_type/confidence（复用 ai_evaluation） |
| 模式挖掘（补 delivery/price/capacity + carrier/route） | 正 | 补齐现有测试缺口（API 审计 D.3） |
| 校准提案仅 proposed，不自动应用 | **负（关键）** | `approve` 前恒为 proposed；**绝不自动改规则/参数** |
| 校准审批防重/拒绝 | 负 | 二次 approve 400；reject 后再 approve 400 |
| 校准回写计划只读 | 正 | writeback-plan 只读；实际回写须人工审批 |
| 校准回写经版本化 + 审计 | 正 | approved 后经 StrategyVersion/规则版本回写，留 event_log |
| profile 回写追溯链 | 正 | risk_score_* + last_calibrated_at + model_version + source_trace_id 写入 |
| 线上抽样复核回流 | 正 | human_rating 写入 + 回流评测集 |

### 3.6 Agent 全链路治理（关键）

| 用例 | 类型 | 断言 |
|---|---|---|
| 任务触发幂等（idempotency_key 复用） | 正/边界 | 同键返回同 task_id |
| Agent 运行写 AgentExecution + event_log | 正 | input/plan/tool_calls/output/cost/trace_id 完整 |
| **预算门禁拦截** | **负** | 投影成本超 monthly_budget → allowed=False → 任务 failed + `agent.execution_budget_blocked` |
| **L3 工具强制审批** | **负（关键）** | L3 工具 → requires_approval → 停 waiting_approval → 进审批中心；**绝不自动执行** |
| **审批过期永不执行** | **负（关键）** | SLA expired → 永不执行、永不自动批准 |
| 中/高风险建议停 pending_approval | **负（关键）** | `AUTO_APPROVE_RISK_LEVELS` 默认仅 low；中高风险不自动批准 |
| 生成 Agent ≠ 审核 Agent | 正 | supply_chain 建议由 business_analyst 互审 |
| 畸形输入终态报错 | 负 | 不静默重试，终态 SupplyChainExecutionError |
| LLM 失败降级不伪造建议 | **负** | LLM 不可用 → 降级规则/人工，**不产出伪造建议** |
| 建议执行路由（低风险） | 正 | 审批通过后经 execution_router 执行，留 execution_result |
| 反馈回流（feedback_score） | 正 | 提交反馈 + learnable 标记 |

### 3.7 工具白名单 + 权限（对齐 API 审计 D.3 缺口）

| L3 工具 requires_approval | 正/负 | 停 waiting_approval，审批后执行 |
| 每次工具调用留 tool_calls 审计 | 正 | AgentExecution.tool_calls 追加（含 status/reason） |
| handler 不直连 DB | 正（架构） | 只经服务层白名单 API |
| 参考 B2B 授权测试模式 | — | 对齐 `test_b2b_credit_api_authorization.py` 模式 |

### 3.8 规则引擎

## 4. Supply Chain Agent 评测集（AGENTS.md §3.4 强制）

| 项 | 要求 |
|---|---|
| 用例数 | **≥ 20**（覆盖五大方向：供应商≥4、成本≥4、采购决策≥5、库存履约≥4、学习闭环≥3） |
| 格式 | 固定 JSON fixture（`backend/tests/fixtures/supply_chain_agent_eval_suite.json`），对齐 `tests/sourcing_evaluation_suite.json` 模式 |
| 评分维度 | 准确性（建议/预测 vs 标注）、合规性（是否越权/违反硬规则）、语气（专业、无夸大） |
| 边界用例 | 缺真实成本（降置信/冻结，不伪造）、1688 未验证数据（不当成交价）、畸形输入（终态报错） |
| 回归 | 提示词/模型变更**必须**跑评测回归；禁止无评测上线 |
| 数据 | **固定测试数据，禁止真实用户数据** |
