# M4.2 Supply Chain Agent — 数据模型设计（Data Model）

> 版本：v1.0
> 日期：2026-11-21
> 阶段：M4.2 第一阶段（现状审计 + 架构设计，不含代码实施）
> 决策身份：ChatGPT Owner
> 执行身份：DSH（执行 Agent）
> 上游依据：`M4.2_GAP_ANALYSIS.md`、`M4.2_AGENT_DESIGN.md`、`docs/AGENTS.md` §2.2/§4
> 基线：现有 ORM 模型为唯一真源（`backend/app/models/`），迁移用 Alembic

---

## 1. 数据模型设计原则

| # | 原则 | 落地 |
|---|---|---|
| DM-1 | **不重复建设** | GAP 分析标记 ✅ 的表一律复用；只对缺口做**增量迁移**（新增字段/表） |
| DM-2 | **多 workspace 隔离** | 所有新表继承 `WorkspaceMixin`（`workspace_id` 不可空 + 索引） |
| DM-3 | **append-only 证据行** | 评估/预测/历史类表用 `CreatedAtMixin`（只增不改）；状态类表用 `TimestampMixin` |
| DM-4 | **操作人可追溯** | 新表一律含 `created_by`（对齐 GAP D-6）；审批类含 `approved_by/at` |
| DM-5 | **全链路 trace_id** | 新表一律含 `trace_id String(64)` 可空（缺省由 `core/tracing` 解析） |
| DM-6 | **证据分级** | 预测/估算类字段配对 `source` + `confidence`；预测 ≠ 实际分字段 |
| DM-7 | **PII 分级** | 供应商合同/报价属 L3 机密，存储遵循 AGENTS.md §4；禁止明文落 JSON 文件 |
| DM-8 | **迁移可回滚** | 每个 Alembic migration 含 `upgrade()` + `downgrade()`，新增列须可空或有 default |

## 2. 现有表增强（增量迁移，不破坏既有数据）

### 2.1 `supplier_profiles` — 供应商风险量化（GAP 方向 A）

现状 `risk_level` 仅字符串（默认 `low`），无量化评分与证据。新增：

| 新增字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `risk_score` | Numeric(5,2) | 可空，0–100 | 量化风险评分（与 `risk_level` 并存，level 由 score 分桶） |
| `risk_score_confidence` | Numeric(4,3) | 可空，0–1 | 评分置信度 |
| `risk_score_source` | String(32) | 可空 | 评分来源（`pattern_mining`/`manual`/`model`） |
| `risk_score_model_version` | String(32) | 可空 | 评分模型版本 |
| `risk_score_calibrated_at` | DateTime(tz) | 可空 | 最近校准时间 |
| `risk_score_source_trace_id` | String(64) | 可空 | 来源校准 run 的 trace_id（**打通 GAP 方向 E「profile 回写追溯链」**） |
| `capacity_monthly_units` | Integer | 可空 | 月产能（GAP 方向 A/E capacity 结构化） |
| `last_evaluated_at` | DateTime(tz) | 可空 | 最近评估时间 |

> 对 `quality_score`/`on_time_rate`/`defect_rate` 同样补 `*_confidence`、`*_updated_at`（证据分级，DM-6）。**迁移须可空 + default，不破坏现有行**。

### 2.2 `product_cost` — 成本主表证据对齐（GAP 方向 B）

现状主表只有 `version`/`valid_from`，证据弱（快照表才有 source/trace_id）。新增，使主表与快照表证据能力对等：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `source` | String(32) default `"manual"` | 成本来源（`manual`/`1688`/`model`/`supplier_quote`） |
| `confidence` | Numeric(4,3) default 0 | 成本置信度（estimate 必须 <0.5，对齐 PO cost_confidence 语义） |
| `trace_id` | String(64) 可空 | 全链路追踪 |
| `created_by` | String(128) 可空 | 操作人（DM-4） |

### 2.3 `inventory_snapshots` — 再订货/安全库存字段（GAP 方向 C/D）

现状仅当前态（quantity/reserved/available/in_transit）。新增预测与再订货字段：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `reorder_point` | Integer 可空 | 再订货点 |
| `safety_stock` | Integer 可空 | 安全库存 |
| `days_of_supply` | Numeric(6,2) 可空 | 可供天数（库存/日均消耗） |
| `avg_daily_demand` | Numeric(8,2) 可空 | 日均需求（由需求预测回写） |
| `demand_forecast_id` | Uuid FK 可空 | 关联最新需求预测（§3.4） |
| `forecast_confidence` | Numeric(4,3) 可空 | 预测置信度 |
| `stockout_risk` | Numeric(4,3) 可空 | 缺货风险概率 |

> 库存**历史序列**问题（GAP D 方向 D）不由本表解决（本表仍 upsert 当前态），而由新增 `inventory_movements`（§3.5）承载 append-only 变动历史。

### 2.4 `shipment_records` — 实际成本与承诺交期（GAP 方向 B/D）

现状有 delivery_time_days/delay_reason（实际值），缺实际运费/关税与承诺交期对账。新增：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `promised_delivery_at` | DateTime(tz) 可空 | 承诺交期（vs `delivered_at` 实际，直接对账） |
| `actual_freight_cost` | Numeric(12,2) 可空 | 实际运费（回灌校准 landed cost） |
| `actual_duty_vat_cost` | Numeric(12,2) 可空 | 实际关税/VAT |
| `cost_reconciled` | Boolean default False | 成本是否已回灌校准 |

### 2.5 `purchase_orders` — 采购审批人审留痕（GAP 方向 C）

现状只有 `cost_confirmed_by`（成本门），缺采购审批人审字段。新增：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `approved_by` | String(128) 可空 | 采购审批人（draft→approved 人审留痕） |
| `approved_at` | DateTime(tz) 可空 | 审批时间 |
| `procurement_decision_id` | Uuid FK 可空 | 关联结构化采购决策（§3.3，打通建议→审批→执行链） |

> 与 `cost_confirmed_by/at` 区分：成本门（数据可信度）+ 采购审批（业务决策）两条独立人审。

## 3. 新增表

### 3.1 `supplier_quote_history` — 供应商报价历史（GAP 方向 A）

现状 `product_sourcing_candidates` 只有单点 `purchase_price`，缺报价有效期/阶梯价/历史。新增 append-only 报价历史表：

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | Uuid PK | |
| `supplier_id` | Uuid FK→`suppliers.id` 可空 index | SET NULL |
| `product_id` | Uuid FK→`products.id` 可空 index | SET NULL |
| `sourcing_candidate_id` | Uuid FK 可空 | 关联候选 |
| `quote_price` | Numeric(12,2) 不可空 | 报价单价 |
| `currency` | String(8) default `"USD"` | |
| `moq` | Integer 可空 | 该报价 MOQ |
| `price_tiers` | AI_JSON 可空 | 阶梯价 `[{min_qty, unit_price}]` |
| `valid_until` | DateTime(tz) 可空 | **报价有效期** |
| `payment_terms` | String(128) 可空 | 付款条件 |
| `lead_time_days` | Integer 可空 | 交期 |
| `source` | String(32) default `"manual"` | 报价来源（`manual`/`1688`/`inquiry`） |

| `created_by` | String(128) 可空 | 录入人 |
| `trace_id` | String(64) 可空 | |
| 审计 | `CreatedAtMixin` + `WorkspaceMixin` | append-only |

### 3.2 `cost_prediction_vs_actual` — 成本预测 vs 实际对账（GAP 方向 B）

现状无"预测成本 vs 实际落地成本"校准实体。新增（学习闭环扩展到成本）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Uuid PK | |
| `product_id` | Uuid FK 可空 index | |
| `purchase_order_id` | Uuid FK 可空 index | 关联实际采购 |
| `predicted_cost` | AI_JSON 不可空 | 预测成本拆解快照（含 confidence/source） |
| `predicted_total_landed_cost` | Numeric(12,2) | 预测落地成本合计 |
| `actual_cost` | AI_JSON 可空 | 实际成本拆解（来自 shipment 实际运费/关税回灌） |
| `actual_total_landed_cost` | Numeric(12,2) 可空 | 实际落地成本 |
| `variance` | Numeric(12,2) 可空 | 偏差（actual − predicted） |
| `variance_pct` | Numeric(6,4) 可空 | 偏差率 |
| `accuracy` | Numeric(6,4) 可空 | 复用 `ai_evaluation` 准确率分类 |
| `confidence_bucket` | String(8) 可空 | LOW/MEDIUM/HIGH |
| `success_flag` | Boolean 可空 | 偏差在阈值内为 success |
| `model_version` | String(32) 不可空 | 成本预测模型版本 |
| `status` | String(16) default `"recorded"` | recorded → (人工) reviewed |
| `human_rating` | Integer 可空 | 人工复核评分 |
| `created_by` / `trace_id` | | DM-4/DM-5 |
| 审计 | `CreatedAtMixin` + `WorkspaceMixin` | append-only |

### 3.3 `procurement_decisions` — 结构化采购决策记录（GAP 方向 C）

现状 `agent_suggestions.supply_chain` 类型非结构化，缺采购专用字段。新增结构化采购决策实体（补足建议→审批→执行的决策链）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Uuid PK | |
| `product_id` | Uuid FK 可空 index | |
| `supplier_id` | Uuid FK 可空 index | **推荐供应商** |
| `alternative_supplier_ids` | AI_JSON 可空 | 替代供应商候选 |
| `recommended_quantity` | Integer 不可空 | **建议采购量** |
| `target_unit_price` | Numeric(12,2) 可空 | 目标价 |
| `moq_satisfied` | Boolean 可空 | MOQ 匹配校验 |
| `expected_arrival_at` | DateTime(tz) 可空 | **预期到货** |
| `reorder_point_at_decision` | Integer 可空 | 决策时再订货点 |
| `demand_forecast_id` | Uuid FK 可空 | 依据的需求预测 |
| `decision_reason` | Text 可空 | 决策理由 |
| `risk_flags` | AI_JSON 可空 | 风险标记 |
| `rule_evaluation_snapshot` | AI_JSON 可空 | 硬规则评估快照（rule_version + 结果） |
| `suggestion_id` | Uuid FK 可空 | 关联 `agent_suggestions` |
| `approval_status` | String(16) default `"pending_approval"` | pending_approval → approved/rejected |
| `approved_by` / `approved_at` | | 人审留痕 |
| `created_by` / `trace_id` | | |
| 审计 | `TimestampMixin` + `WorkspaceMixin` | |

> **治理铁律**：本表记录的是**建议与决策**，不直接生成外发采购单。生成内部采购单须经 `fulfillment_service`（`draft`/`pending_approval`），永不直接 `approved`。

### 3.4 `demand_forecasts` — 需求预测（GAP 方向 C/D 核心前置）

现状**完全缺失**需求预测。新增（采购量/再订货点/缺货风险的前置）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Uuid PK | |
| `product_id` | Uuid FK 不可空 index | |
| `location` | String(32) default `"cn"` | cn/us/eu |
| `forecast_horizon_days` | Integer 不可空 | 预测周期 |
| `forecast_daily_demand` | Numeric(8,2) 不可空 | 预测日均需求 |
| `forecast_total_demand` | Numeric(10,2) 不可空 | 周期内总需求 |
| `confidence` | Numeric(4,3) 不可空 | 预测置信度 |
| `confidence_bucket` | String(8) | LOW/MEDIUM/HIGH |
| `model_version` | String(32) 不可空 | 预测模型版本 |
| `method` | String(32) | 预测方法（`moving_average`/`exponential_smoothing`/`model`） |
| `input_snapshot` | AI_JSON | 输入数据快照（历史销量等） |
| `status` | String(16) default `"active"` | active/superseded |

## 4. 学习闭环扩展（复用 `supply_chain_learning`，不新建骨架）

M4.2 学习闭环**复用** `supply_chain_learning` 现有骨架（GAP 方向 E 标记 ✅），只做**扩展**：

| 扩展点 | 方式 |
|---|---|
| 成本维度 | 新增 `cost_prediction_vs_actual`（§3.2）接入评估/模式挖掘；`SUPPLIER_PATTERN_TYPES` 的 `price_pattern` 校准输出补 `suggested_params`（建议成本/交期系数）结构 |
| 库存/需求维度 | `demand_forecasts` + `inventory_movements` 喂入预测评估；缺货预测准确率纳入 `AgentEvaluation` |
| 校准回写链 | `supply_chain_calibration_runs.approve` 后，定义回写链：经 `StrategyVersion` 或规则版本**人工确认**后更新 `supplier_profiles`（写 `risk_score_*` + `last_calibrated_at` + `model_version` + `source_trace_id`）——**绝不自动应用**，回写本身留审计 |
| 线上抽样复核 | 新增抽样复核任务：从线上建议抽样 → 人工复核 → 写 `human_rating` → 回流评测集（AGENTS.md §3.4） |

> `supply_chain_calibration_runs` 已有 `suggested_weights` 类似结构（product 域 `score_calibration_runs`），成本域对齐此模式补 `suggested_params`。

## 5. 迁移策略（Alembic）

| 项 | 策略 |
|---|---|
| 迁移编号 | 顺延现有 Alembic 版本链（当前至 `0046`+） |
| 增量列 | 一律**可空或有 default**，不破坏现有行（DM-8） |
| 新增表 | `upgrade()` 建表 + 索引 + 约束；`downgrade()` drop table |
| FK 策略 | 引用 `products`/`suppliers` 等用 `ondelete=SET NULL`（保留历史）；子项用 CASCADE |
| JSON 列 | 用 `AI_JSON`（PG=JSONB，其他=JSON） |
| 往返测试 | 迁移须通过 `upgrade`→`downgrade`→`upgrade` 往返测试（对齐现有集成测试 `test_*_migrations.py` 模式） |
| **本轮不执行** | 迁移文件属代码实施，**Owner 审批后**才编写与运行 |

## 6. 明确不改动项（避免越界）

| 表/域 | 不改动理由 |
|---|---|
| `orders` / `order_items` | 订单域已稳定（PII 策略正确：只存国家非识别字段）；需求预测**只读**消费订单数据，不改订单表 |

| B2B 相关表（b2b_*） | B2B 规模化属 M6，M4.2 不触碰 |
| JSON 文件版存储（D-1） | 标记遗留，本轮不迁移不改写 |

## 7. 数据分级与安全（AGENTS.md §4）

| 数据 | 级别 | 处理 |
|---|---|---|
| 供应商报价 / 合同 | L3 机密 | 加密存储、最小权限；`supplier_quote_history` 含商业敏感报价，访问留痕 |
| 供应商联系方式 | L4 PII | `suppliers.contact` JSON 需注意；禁止明文落 JSON 文件（收口 D-1） |
| 成本 / 供应商绩效 | L2 内部 | 仅限内部，禁止外发 |
| 需求预测 / 库存 | L2 内部 | 经营数据，仅内部 |
| 日志/提示词 | — | 禁止出现 PII 明文；需要时脱敏 |
