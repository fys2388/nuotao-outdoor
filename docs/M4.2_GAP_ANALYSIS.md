本文档是 M4.2 Supply Chain Agent 设计阶段的**基线输入**。它回答三个问题：

1. **M4.1 + M4.2 预研已经有什么**（现状能力清单，精确到表 / 服务 / 函数）。
2. **M4.2 Supply Chain Agent 要达到什么**（五大方向目标能力）。
3. **现状与目标之间的差距（GAP）**，以及必须正视的**架构债**。

所有后续设计文档（ARCHITECTURE / AGENT_DESIGN / DATA_MODEL / API_SPEC / RULES_DESIGN / TEST_PLAN / IMPLEMENTATION_ROADMAP / RISK_REGISTER）均以本文档的 GAP 清单为依据，**不重复建设已有模块**。

## 2. 阶段边界（Owner 约束）

M4.2 现阶段的边界由 Owner 明确锁定：

- ✅ **本轮只做**：现状审计 + 架构设计 + 实施计划 + 风险登记。
- ❌ **本轮不做**：业务代码实施、数据库迁移、Agent 上线、生产配置变更。
- ❌ **M4.2 ≠ 自动采购授权**：所有采购建议必须可追溯，采购执行、规则修改仍须人工审批。
- ❌ **不得因进入 M4.2 而删除、降低或绕过 D8-E 遗留安全事项**（见 `docs/acceptance/OWNER_PENDING_ACTIONS.md`）。

> Supply Chain Agent 的定位遵循 `AGENTS.md` §3.1：**Agent 是「提议者」不是「执行者」**。高风险动作（下单、改价、补货执行、删除）必须进入审批队列，人工确认后执行。

## 3. 现状能力清单（M4.1 + M4.2 预研）

### 3.1 数据层（`backend/app/models/`）

| 域 | 表 | 关键能力 | 证据/可追溯 |
|---|---|---|---|
| 供应商 | `suppliers` | 主数据（code/name/platform/rating/status/contact） | `TimestampMixin` |
| 供应商 | `supplier_profiles` | 智能画像（quality_score/on_time_rate/defect_rate/lead_time_days/minimum_order_qty/risk_level/certifications） | `trace_id` |
| 采购 | `purchase_orders` | 采购单 + **成本确认门控**（cost_confirmed/cost_source/cost_confidence/cost_block_reason）+ 状态机 | `trace_id`、`cost_confirmed_by/at` |
| 采购 | `purchase_order_items` | PO 行项（sku/quantity/unit_cost/line_total） | 无独立审计 |
| 成本 | `product_cost` | 落地成本拆解（PROFIT-001，total_landed_cost） | `version`/`valid_from`（证据弱） |
| 成本 | `product_cost_snapshots` | 成本历史（append-only，含 source/trace_id） | ✅ |
| 寻源 | `product_sourcing_candidates` | 单商品多供应商候选（purchase_price/moq/lead_time_days/trend_score） | `trace_id` |
| 库存 | `inventory_snapshots` | CN/US/EU 三地当前库存（quantity/reserved/available/in_transit） | `trace_id`、`snapshot_time`（upsert 非历史） |
| 履约 | `shipment_records` + `logistics_events` | 运单 + append-only 物流轨迹（carrier/tracking/delivery_time_days/delay_reason） | `trace_id` |
| 订单/现金 | `orders` / `settlements` / `exchange_rates` | 订单（profit_snapshot/rule_results 快照）+ 回款台账 + 不可变汇率证据 | `trace_id`、`created_by`（汇率） |
| 知识 | `supply_chain_knowledge_entries` | 供应链知识记忆（11 类 entry_type，source/confidence/trace_id） | ✅ 证据最完整 |
| **M4.2 学习层** | `supplier_ai_evaluations` / `logistics_ai_evaluations` | 预测 vs 实际评估（accuracy/confidence/success_flag/human_rating） | `trace_id`、append-only |
| **M4.2 学习层** | `supplier_pattern_runs` / `logistics_pattern_runs` | 确定性模式挖掘（quality/delivery/price/risk/capacity；delay/carrier/route/country） | `trace_id` |
| **M4.2 学习层** | `supply_chain_calibration_runs` | 校准提案（**proposed→人工 approved/rejected，永不自动应用**） | `approved_by/at`、`trace_id` |

| 服务 | 核心职责 | M4.2 归类 | 关键约束 |

## 4. GAP 分析（对照 M4.2 五大方向）

图例：✅ 已有 · 🟡 部分有 · ❌ 完全缺失

### 方向 A：供应商智能分析（Supplier Intelligence）

| 能力 | 现状 | GAP |
|---|---|---|
| 供应商主数据 + 智能画像 | ✅ `suppliers` + `supplier_profiles` | — |
| 供应商预测 vs 实际评估 | ✅ `supplier_ai_evaluations` + `record_supplier_evaluation` | — |
| 供应商模式挖掘 | 🟡 确定性统计聚合（均值/分布/计数），5 类 pattern | 非**预测性评分模型**；缺 delivery/price/capacity 测试覆盖 |
| **供应商综合风险/绩效评分卡** | ❌ `risk_level` 仅 `low` 字符串，**无量化 risk_score / confidence / 评分版本 / 更新时间** | 需新增量化评分 + 证据字段 |
| **供应商比价与替代推荐** | ❌ `product_sourcing_candidates` 有 price/moq/lead_time，但无比价逻辑、无报价历史 | 需新增比价 + 报价历史 |
| **报价维度** | ❌ 无报价有效期(valid_until)、阶梯价(price tiers)、付款条件 | 需新增字段/表 |
| 供应商询价采集 | 🟡 `auto_inquiry_service`（RFQ，JSON 日志、无 trace） | 需规范化接入事件审计 |

### 方向 B：采购成本智能核算（Procurement Cost Intelligence）

| 能力 | 现状 | GAP |
|---|---|---|
| 落地成本/边际贡献确定性计算 | ✅ `cost_model_service` + `profit_engine` | — |
| 成本置信度模型 | ✅ KNOWN/ESTIMATED/UNKNOWN，UNKNOWN 拒绝高置信结论 | — |
| 采购单成本门控 | ✅ `purchase_orders` cost_confirmed 门 + `fulfillment_service.pending_cost_confirmation` | — |
| **成本主表证据字段** | ❌ `product_cost` 无 source/confidence/trace_id/created_by（快照表才有） | 需对齐主表与快照证据能力 |
| **动态/真实成本获取** | 🟡 多处硬编码（关税率表、运费 $/kg、营销 15%、缺成本按售价 40% 估） | 需参数化 + 真实运费/关税源 |
| **成本预测 vs 实际对账** | ❌ 无"预测成本 vs 实际落地成本"校准实体；`shipment_records` 无实际运费/关税金额 | 需新增成本校准实体 + 实际成本回灌 |
| **采购价格变化监控** | ❌ 缺 1688 采购价变化的监控与告警 | 需新增价格监控 |

| 能力 | 现状 | GAP |

### 方向 E：供应链学习闭环（Supply Chain Learning Loop）

| 能力 | 现状 | GAP |
|---|---|---|
| 供应商/物流评估 → 模式挖掘 → 校准提案 → 人工审批 | ✅ `supply_chain_learning` 完整骨架，**永不自动应用** | — |
| **学习闭环扩展到成本/库存/需求** | 🟡 仅覆盖供应商绩效 + 物流时效两类 | 需扩展到成本、库存、需求预测 |
| **校准提案 → 回写业务参数的执行链** | ❌ `approve` 仅改状态，**未定义如何回写规则/模型参数** | 需定义人审后的回写链（经 StrategyVersion/规则版本） |
| **profile 分数回写校准链** | ❌ `supplier_profiles` 分数无 last_calibrated_at/model_version/source_trace_id | 需新增可追溯字段 |
| **线上抽样复核回流** | ❌ 缺线上结果抽样人工复核 → 评测集回流机制 | 需新增 |

### 横切架构债（必须 M4.2 收口或明确边界）

| 编号 | 架构债 | 影响 | M4.2 处置 |
|---|---|---|---|
| **D-1** | **采购/履约双轨存储分裂**：DB 版（`fulfillment_service`/`purchase_automation_service`/`procurement_service`，表 `purchase_orders`）vs JSON 文件版（`purchase_order_service`/`overseas_warehouse`/`logistics_monitor`/`auto_inquiry`/`newton_cost_monitor`，存 `backend/data/*.json`） | 数据不一致、PII 明文落 JSON、无 trace/事件、两套状态机 | **收敛**：M4.2 一律以 DB 版 `purchase_orders`（`fulfillment_service` 范式）为唯一采购单真源；JSON 版标记为遗留，M4.2 不扩展，迁移动作列入路线图（本轮不实施） |
| **D-2** | **采购单三套状态机并存**：`supply_chain.py`(draft/approved/ordered/partial_received/received/cancelled)、`fulfillment.py`(含 shipped/delivered/completed)、`procurement_workbench.py`(pending/confirmed/ordered/shipped/completed/cancelled) | Agent 无法用单一状态模型 | **统一**：以 M4.1 `purchase_orders.PO_STATUSES` 为准，其余标记 deprecated |
| **D-3** | **库存/物流多体系并存**：M4.1 `inventory_snapshots`/`shipment_records`（规范、有审计）vs `inventory.py`/`logistics.py`（服务层、无审计、无 workspace） | Agent 数据源不唯一 | **统一**：Agent 工具只对接 M4.1 规范表 |
| **D-4** | **事件/审计不一致**：仅 `supply_chain_learning` 全程 event_service + trace_id；其余仅 logger 或 JSON history | 不满足 AGENTS.md「全链路可审计」 | **强制**：M4.2 新增/触达的服务一律 event_service + trace_id |
| **D-5** | **成本估算静默降级**：多处缺真实成本按比例兜底且标记不一致 | 污染决策风险 | **强制**：沿用 `fulfillment_service` 规范（缺真实成本即冻结/降置信度，禁止伪造） |
| **D-6** | **`created_by`/`updated_by` 系统性缺失**：多数供应链表无操作人字段 | 审计轨迹不完整 | M4.2 新增表补 created_by；存量表按需补（列入路线图） |
| **D-7** | **`supply_chain_manager.py` 走 generic 路径**：提示词代码常量、未接 M5 运行时、无版本化绑定、无工具白名单 | 与运行时并存风险 | **升级**：迁移提示词进 Prompt Registry、绑 `AGENT_SUPPLY_CHAIN_MANAGER`、接 executor、接工具白名单 |
| **D-8** | **三套 PO 状态机 + 原生 SQL 旁路**：`supply_chain.py` 末尾 `/purchase-orders/stats`、`PATCH /status` 绕过服务层、状态集不一致、无审计 | 一致性风险 | **标记技术债**，M4.2 不依赖，收口列入路线图 |

## 6. 一句话结论

M4.1 + M4.2 预研已落地"供应商档案 + 采购单（含成本确认门控）+ 落地成本 + 库存 + 履约追踪 + 订单/结算/汇率 + 供应链知识与学习闭环 + 成熟 Agent 基础设施（注册/运行时/审批/规则/白名单/审计）"的完整骨架，`trace_id` 与人审门控到位，**Product Analyst 是 M4.2 可直接对齐的模板**。核心 GAP 集中在——**需求预测与采购量模型（采购决策的前置）、供应商风险量化与比价、成本预测 vs 实际对账、库存历史序列与再订货字段、结构化采购决策记录实体、学习闭环向成本/库存扩展与校准回写链**，以及**必须收口的架构债**（采购单双轨存储 D-1、三套状态机 D-2/D-8、Agent 直建 approved 绕审批的治理漏洞、`created_by` 缺失 D-6）。这些构成 M4.2 后续设计文档的设计输入。
