## 1. Agent 身份注册（AgentRegistry）

Supply Chain Agent 在 `agents` 表由 `AgentRegistry` 一行声明，对齐 Product Analyst 注册模式（`ensure_product_analyst_agent()`）：

| 字段 | 值 | 说明 |
|---|---|---|
| `agent_id` | `supply_chain_analyst` | 逻辑 ID（workspace 内唯一）。区别于现有 generic 路径的 `supply_chain_manager`（见 §7 升级策略） |
| `name` | `Supply Chain Analyst` | 展示名 |
| `description` | 供应商智能 / 采购成本核算 / 采购决策辅助 / 库存履约预测 / 供应链学习闭环 | 五大能力概述 |
| `domain` | `supply_chain` | `AGENT_DOMAINS` 已含此域 |
| `version` | `v1` | 注册版本 |
| `model_provider` / `model_name` | 经 LiteLLM Gateway 路由 | 遵循 P4 单一网关 |
| `prompt_version` | `v1` | 绑定 Prompt Registry 活跃版本 |
| `permission_level` | **`L2`** | 对齐 Product Analyst：仅分析 + 提案；**禁止** approve/publish/purchase/allocate |
| `business_scope` | `SHARED` | 供应链能力 B2C/B2B 共享（采购/库存/履约为双模式底座） |
| `status` | `draft` → Owner 审批后 `active` | 生命周期受控 |

**注册前置**（`register_agent` 强制）：必须先存在一条 active 的版本化提示词，命名 `AGENT_SUPPLY_CHAIN_ANALYST`。播种函数建议命名 `ensure_supply_chain_analyst_agent()`（对齐 `ensure_product_analyst_agent()`），幂等。

## 2. 提示词设计（Prompt Registry 版本化）

提示词视为代码，入库版本化（P6 / AGENTS.md §3.2），**禁止散落在字符串常量**。现状 `supply_chain_manager.py` 的 `PROMPT_TEMPLATE` 是代码常量——M4.2 须迁移进 Prompt Registry。

| 项 | 设计 |
|---|---|
| Prompt name | `AGENT_SUPPLY_CHAIN_ANALYST` |
| 版本 | `v1`（`status=active`） |
| 模板变量 | `context_json`（工具返回的结构化上下文）、`output_schema`（强制输出 JSON schema）、`rules_context`（激活的硬规则摘要，供模型自检） |
| 渲染校验 | `render_prompt()` 双向校验占位符与 `variables` 声明（缺声明抛 `PromptRegistryError`） |

**提示词职责边界**（防越权）：
- 提示词明确告知模型：你是**分析者与提议者**，你的输出是**建议**，不是指令；你**不能**下单、不能改规则、不能发布商品。
- 输出必须结构化（JSON），经 Pydantic schema 校验；解析失败走重试/降级，不静默吞掉（AGENTS.md §3.2）。

> 提示词全文在实施阶段撰写并入库；本设计只锁定变量契约与职责边界。

## 3. 工具白名单（AgentTool + Tool Gateway）

Supply Chain Agent 可调用的工具在 `agent_tools` 注册，经 `tool_gateway` 三层门禁。**读类工具 L0-L2，任何执行/写入类工具 L3（强制进审批，绝不自动执行）**。

### 3.1 读类工具（L1，allowed）

| tool_name | 权限 | 数据源（服务层） | 输出 |
|---|---|---|---|
| `query_supplier_profile` | L1 | `supplier_profiles` | 供应商画像（质量分/准时率/交期/MOQ/risk_level） |
| `query_sourcing_candidates` | L1 | `product_sourcing_candidates` | 单商品多供应商候选（price/moq/lead_time） |
| `query_landed_cost` | L1 | `product_cost` / `profit_engine` | 落地成本拆解 + 成本置信度 |
| `query_inventory` | L1 | `inventory_snapshots` | 当前库存（含新增 reorder_point/safety_stock） |
| `query_shipments` | L1 | `shipment_records` / `logistics_events` | 物流时效 / 延误历史 |
| `query_supply_chain_knowledge` | L1 | `supply_chain_knowledge_entries` | 供应链知识记忆 |
| `query_supplier_evaluations` | L1 | `supplier_ai_evaluations` / `supplier_pattern_runs` | 供应商预测vs实际 / 模式 |
| `query_procurement_rules` | L1 | `rule_engine`（只读评估） | 激活的供应链硬/软规则 |

### 3.2 提议/执行类工具（**L3，requires_approval**）

| tool_name | 权限 | 动作 | 落地 |
|---|---|---|---|
| `generate_procurement_recommendation` | **L3** | 生成采购建议（推荐供应商/目标价/采购量/理由） | 写 `procurement_decisions` + `agent_suggestions`（`pending_approval`） |
| `create_restock_suggestion` | **L3** | 生成补货建议（基于需求预测/再订货点） | 写 `agent_suggestions`（`inventory_restock` 类型） |
| `request_supplier_quote` | **L3** | 发起 1688 询价（RFQ，非下单） | 经规范化后的询价服务（补 trace_id + event_service） |

> **L3 工具结构上不可能自动执行**：`permission_engine.requires_approval(L3)=True` → 停 `waiting_approval` → 进审批中心 → 只有 `approve_execution` 后才继续；审批过期 `expired` 永不执行。

### 3.3 工具 handler 约束

- 每个 handler 经 `tool_gateway.register_handler(name, fn)` 绑定执行体。
- handler **不得直连 DB**，只通过服务层白名单 API 取数，返回 JSON-safe dict（P3 / AGENTS.md §2.3）。
- 工具只传递任务必需字段，禁止把整表数据或无关客户 PII 塞入上下文（AGENTS.md §3.1 上下文最小化）。

## 4. 执行器设计（Executor + Context Builder）

对齐 `worker/product_analyst_executor.py` 模式，新增 `worker/supply_chain_executor.py::supply_chain_executor`，注册进 `resolve_executor(agent)`。

### 4.1 执行器流程

```
解析输入（畸形输入 → 终态 SupplyChainExecutionError，不静默重试）
  → Context Builder（组装供应商/库存/成本/物流/知识/规则上下文）
  → LLM Gateway（渲染 AGENT_SUPPLY_CHAIN_ANALYST 提示词）
  → 结构化输出 + Pydantic schema 校验
  → 硬规则校验（rule_engine.check() gate）
  → 写审计行（AgentExecution.context_snapshot 合并 analysis_run_id）
  → 产出建议（agent_suggestions，pending_approval）
  → record_agent_evaluation（预测 vs 实际，回流学习闭环）
```

### 4.2 权限硬约束（对齐 Product Analyst docstring 范式）

- **READ**：仅供应链智能数据（供应商/库存/成本/物流/知识/规则）。
- **WRITE**：仅 `supply_chain` 域的分析运行行 + pending `agent_suggestions` + 评估行。
- **FORBIDDEN**：approve / publish / purchase（外发下单）/ campaign / 直接改库存。L3 工具在 `waiting_approval` 停住。

### 4.3 Context Builder 组装

| 数据域 | 来源工具 | 用途 |
|---|---|---|
| 供应商 | `query_supplier_profile` + `query_sourcing_candidates` | 供应商画像、候选比价 |
| 库存 | `query_inventory` | 当前库存、再订货点、安全库存 |
| 成本 | `query_landed_cost` | 落地成本 + 置信度 |
| 物流 | `query_shipments` | 交期、延误历史 |
| 知识 | `query_supply_chain_knowledge` | 历史模式、经验 |
| 规则 | `query_procurement_rules` | 硬约束（MOQ、成本上限、安全库存策略） |

## 4A. 五大能力 → Agent 行为映射

| 能力方向 | Agent 产出（结构化建议） | 关键输入 | risk_level |
|---|---|---|---|
| ① 供应商智能分析 | 供应商风险评分卡、比价与替代推荐 | 画像 + 候选 + 评估历史 | low-medium（建议类） |
| ② 采购成本智能核算 | 成本核算结果、成本波动预警、预测vs实际偏差 | 落地成本 + 实际运费/关税 | low（核算）/ medium（预警） |
| ③ 采购决策辅助 | **采购建议**（推荐供应商/目标价/采购量/时机/理由） | 需求预测 + 库存 + 再订货点 + 比价 | **medium-high**（补货执行类 → 强制人审） |
| ④ 库存与履约预测 | 需求预测、缺货风险、延误风险、海外仓切换测算 | 库存历史 + 销量 + 物流时效 | low-medium（预测类） |
| ⑤ 供应链学习闭环 | 校准提案（**仅提议，永不自动应用**） | 评估 + 模式挖掘 | medium（规则相关 → 强制人审） |

> **核心区分**：预测/核算/分析类输出是**信息**（low risk）；采购/补货/规则校准类输出是**行动建议**（medium-high risk → 强制人审）。

## 5. 建议产出规范（agent_suggestions）

Supply Chain Agent 的行动建议写入 `agent_suggestions`，对齐 `SUGGESTION_TYPES`（已含 `supply_chain`、`inventory_restock`）：

| 字段 | 填充 |
|---|---|
| `agent_id` | `supply_chain_analyst` |
| `agent_run_id` | FK → `ai_agent_runs`（运行审计） |
| `suggestion_type` | `supply_chain` / `inventory_restock` / `pricing_adjustment`（按场景） |
| `title` / `description` / `expected_impact` | 结构化描述 |
| `priority` | high/medium/low |
| `risk_level` | 补货/采购执行类 = medium/high（强制人审）；分析类 = low |
| `execution_params` | 结构化执行参数（如推荐供应商 id、目标价、采购量、MOQ 匹配、预期到货）——**对齐 GAP D 方向 C 缺口，需结构化而非自由文本** |
| `execution_action` | 路由到 `execution_router` 的 handler |
| `dedup_key` | 幂等键（防重复建议） |

**建议 → 审批 → 执行**：中/高风险停 `pending_approval` 等人工；审批通过后低风险经 `execution_router` 路由执行，中高风险停在 `approved` 等调度。**生成 Agent ≠ 审核 Agent**（`supply_chain → business_analyst` 互审）。

## 6. 评测集（AGENTS.md §3.4 强制 ≥20 用例）

Supply Chain Agent 上线前必须有评测集与评分标准，**禁止无评测直接上线**。

| 维度 | 要求 |
|---|---|
| 用例数 | **≥ 20 个代表性用例**（覆盖五大方向） |
| 评分标准 | 准确性（建议/预测与标注一致性）、合规性（是否越权提议、是否违反硬规则）、语气（专业、无夸大） |
| 用例分布 | 供应商分析 ≥4、成本核算 ≥4、采购决策 ≥5、库存履约预测 ≥4、学习闭环 ≥3 |
| 边界用例 | 缺真实成本（应降置信度/冻结，不伪造）、1688 未验证数据（不得当成交价）、畸形输入（终态报错不重试） |
| 回归 | 提示词/模型变更必须跑评测回归 |

> 评测集 fixture 与回归框架在 `M4.2_TEST_PLAN.md` 详述。评测用固定数据，**禁止用真实用户数据**（AGENTS.md §2.5）。

## 7. `supply_chain_manager` 升级策略（GAP D-7）

现状 `agents/supply_chain_manager.py` 走 generic 路径（`run_generic_agent` + `AiAgentRun`，提示词为代码常量 `PROMPT_TEMPLATE`，未接 M5 运行时、无版本化绑定、无工具白名单）。

**M4.2 决策：升级而非并存。**

| 步骤 | 动作 |
|---|---|
| 1 | 将 `PROMPT_TEMPLATE` 领域逻辑迁移进 Prompt Registry（`AGENT_SUPPLY_CHAIN_ANALYST`），版本化 |
| 2 | 注册 `AgentRegistry(agent_id="supply_chain_analyst", permission_level=L2)` |
| 3 | 实现自定义 executor（§4），接工具白名单（§3） |
| 4 | generic 路径的 `supply_chain_manager` 标记 deprecated（保留只读兼容期，列入路线图下线） |

> 避免两条路径并存导致的行为不一致与审计盲区。

## 9. 不可突破的业务约束（对齐 Owner 指令）

| 约束 | Agent 设计中的落地 |
|---|---|
| 商品事实必须有来源和证据等级 | 工具只返回带 source/evidence/confidence 的数据；无证据数据降置信度 |
| 1688 未验证数据 ≠ 真实采购成交价 | 成本工具标注 cost_source；estimate 不得当 actual |
| 预测成本 ≠ 实际成本 | 预测/实际分字段，预测标 confidence，不得混用 |
| AI 不得自行下采购订单 | 外发下单工具**不存在**；内部采购单走审批，永不直接 approved |
| AI 不得自行修改硬性业务规则 | 规则只读评估；校准仅提议，人工审批后经版本化回写 |
| 不自动发布未审核商品 | Agent 无 publish 工具 |
| 重要决策保留 trace_id / 规则版本 / 数据来源 / 决策理由 | 全链路 trace_id；建议含 reasons + 规则评估快照 |
| 数据写入遵循 event_service + 审计架构 | executor 全程 event_service + AgentExecution |
| 不得扩权到生产配置/支付/GA4/B2B 获客/凭据 | 权限 L2 + 工具白名单结构隔离 |
